# Claude Code 터미널의 입력을 Mori 입력창으로 — 설계

2026-11-12. 고르는 창 설계(`2026-11-11-mori-claude-pickers-design.md`)의 3단계(§9 "터미널 입력칸 감추기")를 넓힌 글이다. §9와 다른 곳은 이 글이 앞선다. 본 설계 §3의 결정 217을 바꾸고, 223~226을 더한다(§10).

## 1. 무엇을, 왜

사용자의 말(2026-11-12):

> 지금 터미널 전체가 보여지고 있는데 입력란은 웹앱에서의 입력란만 허용하고 터미널 자체의 입력란부터 그 아래 statusline은 보이지 않게 할 수 있나? 대신 그 정보들은 웹앱에서 깔끔한 ui로 제공하는거지.

> 위쪽 화살표로 지난 글 불러오기 기능은 웹앱에서 지원하도록 기능구현해줘. 빈 입력칸의 흐린 안내, 제안 기능도 웹앱의 입력창에서 지원되었으면 좋겠어.

지금은 Claude Code의 화면이 다 보인다. 맨 아래에 터미널의 입력칸(가로줄, `❯` 줄, 가로줄)과 상태 줄, 모드 줄이 있고, 그 아래에 Mori의 입력창이 또 있다. 입력하는 곳이 둘이라 헷갈린다. 터미널 입력칸에 글이 들어가면 다음에 보내는 글과 섞인다. 상태 줄은 터미널 글꼴과 글자 배치 그대로라 폰에서 읽기 어렵다.

### 1.1 사용자가 정한 것(질문 창, 2026-11-12)

- 터미널의 입력칸부터 그 아래 상태 줄과 모드 줄까지 감춘다. 그 정보는 Mori 화면으로 보인다.
- 상태 줄은 **조각으로 나눠 칩으로** 보인다. `│`로 나뉜 조각은 칩으로, `N%`가 있는 줄은 작은 막대로 그린다. 모드는 단추가 된다. 나눌 수 없는 줄은 글 그대로 보인다.
- 흐린 안내와 실제 글을 가르는 방법은 **실제 화면을 보기 전용으로 한 번 녹화해** 확인했다(§2.1).
- ↑로 불러오는 지난 글은 **Claude Code의 기록**(`history.jsonl`)에서 가져온다. 못 읽으면 Mori에서 보낸 글로 물러난다.
- 흐린 안내와 제안은 Mori 입력창에서도 보인다.
- 덮개가 있을 때 PC에서는 **빈 입력창의 Esc와 Ctrl+글자가 터미널로 간다**(Ctrl+V 붙여 넣기는 뺀다). Claude Code 입력칸에서처럼 Esc 한 번에 일이 멈추고, 쉬는 동안 Ctrl+C를 두 번 누르면 Claude Code가 끝난다는 것을 알고 골랐다(§4.1).

### 1.2 목표가 아닌 것

- `@` 파일 찾기, Ctrl+R 기록 찾기, 대기 글 되돌리기. 필요하면 "터미널 입력칸 보기"를 켜고 터미널에서 한다(§3.4).
- 상태 줄을 그리는 명령(사용자 설정)을 바꾸거나 읽는 것. Mori는 화면에 그려진 글만 읽는다.
- 클래식 화면(normal 버퍼). 사용자의 세션은 fullscreen(alternate 버퍼)이다. 클래식 화면은 덮지 않고 지금처럼 보인다.

### 1.3 이러면 실패다

- 덮개가 실제 글을 가려, 다음 보내기에 보이지 않는 글이 섞인다.
- 덮개나 상태 띠가 터미널 크기를 바꿔 Claude Code가 다시 그린다(결정 219에서 본 흔들림).
- 고르는 창, 승인 요청, 오류처럼 답해야 할 것을 가린다.

## 2. 확인한 사실

### 2.1 녹화(2026-11-12, 이 대화 터미널 t5, 87초)

실제 Mori에 임시 기기를 짝지어 보기 전용(`observe=1`, 키·크기·초점을 보내지 않음)으로 출력 흐름을 받았고, 끝난 뒤 기기를 지웠다. 원시 녹화는 git이 무시하는 `.dev/rec/`에만 있다. xterm에 다시 흘려 입력칸 `❯` 줄(위에 가로줄이 있는 줄)의 글자 속성을 읽었다.

| 입력칸 | 속성 |
|---|---|
| 친 글(`abc`, 조합 중인 `ㅁ`, 보낸 메시지) | 기본 글자색 |
| 안내 글(`describe a task for a new session`, 1초쯤) | `rgb(153,153,153)`, 흐림(SGR 2)이 **아님** |
| `❯` | 일하는 동안 `rgb(153,153,153)`, 쉬는 동안 기본색 |

쉬는 동안 다음 말 제안은 뜨지 않았다(사용자도 보지 못했다). 그래서 "안내나 제안"은 **기본색이 아닌 글**로 가른다. 기본색 글이 한 칸이라도 있으면 실제 글이다(§4.2).

### 2.2 화면 맨 아래(fullscreen, 195×38, 이 대화)

```
────────────────────────────── (입력칸 위 가로줄)
❯ 
────────────────────────────── (입력칸 아래 가로줄)
  Opus 5.5 │ ✍️ 17% │ ⚡  Mori (main) │ ◑ xhigh          (상태 줄, 사용자 설정)
  current ○○○○○○○○○○   6% ⟳ 4:00오전
  weekly  ○○○○○○○○○○   1% ⟳ 11월 15, 1:00오후
  ⏵⏵ bypass permissions on · 1 shell                     (모드 줄, Claude Code)
```

일하는 동안의 표시(`✻ Working… (esc to interrupt)`)는 입력칸 위에 있다. 고르는 창이 뜨면 입력칸부터 아래가 모두 사라진다(고르는 창 설계 §6.2).

### 2.3 Claude Code의 기록 `history.jsonl`

`$CLAUDE_CONFIG_DIR/history.jsonl`, 없으면 `~/.claude/history.jsonl`. 형식은 내부의 것이고 판마다 바뀔 수 있다. 2026-11-12에 본 모양(내용은 읽지 않고 열쇠와 값의 종류만 봤다):

- 한 줄에 JSON 하나이고, 오래된 것부터 붙는다.
- `display`(문자열), `pastedContents`(객체: 번호 → `{id, type, content}` 또는 `{id, type, contentHash}`), `timestamp`(ms), `project`(절대 경로), `sessionId`.
- 빗금 명령도 한 줄이다(`/model` 같은 것).
- 붙여 넣은 글은 `display`에 `[Pasted text #N +k lines]`로 남고, 내용은 `pastedContents`에 있거나 해시로만 있다.

## 3. 덮개와 상태 띠

### 3.1 덮는 것

- 화면 맨 아래의 입력칸(위 가로줄부터)과 그 아래 모든 줄, 화면의 마지막으로 쓴 줄까지.
- 입력칸은 고르는 창 설계 §6.2의 것과 같다(가로줄, `❯`로 시작하는 줄들, 가로줄). 그 아래 줄은 무엇이든 덮는다. 상태 줄의 형식은 사용자 설정이기 때문이다.
- 덮는 자리에는 Mori의 **상태 띠**가 그려진다(§3.3). 띠는 덮은 줄의 높이(줄 수 × 칸 높이)를 그대로 쓴다. 빈 띠가 남지 않는다.
- pty 크기는 바꾸지 않는다(결정 7, 219). 2026-11-12 결정 228로 바뀜: 띠의 판이 덮지 않는 줄만큼 터미널을 늘려, 출력이 판 바로 위까지 오고 남은 줄은 칸 밖으로 나간다.

### 3.2 덮지 않을 때

- **입력칸에 실제 글이 있을 때**(§4.2): 다른 기기에서 터미널에 쳤을 때 같은 것. 덮지 않고, 입력창 위에 "터미널 입력칸에 글이 있습니다 — 보내면 그 뒤에 이어 붙습니다"를 띄운다. 처음 뜰 때 한 번 `announce`를 한다.
- **입력칸을 알아보지 못했을 때**, 클래식 화면, 고르는 창이 떠 있을 때(입력칸이 없다).
- **"터미널 입력칸 보기"를 켰을 때**(§3.4).
- **Claude Code 터미널이 아니거나, "Claude Code 창 알아보기"(고르는 창 설계 §6.9)를 껐을 때.**
- **이 기기의 화면이 터미널 크기와 다를 때**(다른 기기가 크기를 정해 터미널 칸 안에서 스크롤될 때, 결정 125)와 **보기 전용일 때**. 덮을 줄이 맨 아래에 다 보이지 않거나, 입력창이 없기 때문이다(내가 정함).
- **입력창이 보내는 중일 때**에는 덮개를 그대로 둔다. Mori가 보낸 글이 잠깐 입력칸에 들어가도 덮개를 걷거나 "글이 있습니다"를 띄우지 않는다(내가 정함).

### 3.3 상태 띠

astryx: 칸들은 Badge(정보 칩), `N%` 줄은 ProgressBar, 모드는 Button(secondary, sm). 띠는 터미널 칸(`.term-stage`) 안 아래쪽에 붙고(`position: absolute`), 층은 4(고르는 창 패널과 같은 층, 둘은 함께 뜨지 않는다)다. 바탕은 `--color-background-surface`, 위에 1px 선.

- **상태 줄 읽기:** 덮은 줄에서 입력칸 아래 가로줄 다음부터, 모드 줄을 뺀 줄들이다. 줄마다:
  - `N%`와 막대 글자(`○●◐◑▮▯■□█░▒▓` 같은 것)가 있으면 **막대 줄**이다. 앞의 이름(`current`), 막대(`.bar`, N%), 뒤의 글(`⟳ 4:00오전` → "4:00오전")로 그린다.
  - 아니면 `│`(또는 ` | `)로 나눈 조각마다 칩 하나다. 조각 앞뒤 빈칸은 뺀다. 그림 글자(`✍️ ⚡ ◑`)는 칩 안에 그대로 둔다.
  - 나눌 수 없으면 글 그대로 한 줄이다.
- **모드 줄:** 맨 아래 줄이 `⏵⏵`, `⏸`, `?`로 시작하면 모드 줄이다(고르는 창 설계 §9.5).
  - 이름은 아이콘 뒤에서 ` on` 앞까지다. 아는 이름은 우리말이다: accept edits → 편집 자동 허락, plan mode → 계획, bypass permissions → 묻지 않음, auto mode → 자동. `? for shortcuts`면 "기본"이다. 모르는 이름은 그대로 쓴다.
  - ` · ` 뒤의 조각(`1 shell`)은 칩이다. `N shell(s)` → "셸 N".
  - **모드 단추** "모드: <이름>"은 누르면 Shift+Tab을 보낸다(옮기는 키, `expect` 없음). PC는 입력창 줄 왼쪽, 폰은 상태 띠 첫 칸(44px)이다. 띠가 내려간 동안(고르는 창, 입력칸에 글, 터미널 입력칸 보기)에도 PC의 단추는 마지막으로 읽은 모드로 남는다(고르는 창 설계 §9.5와 같다).
- **좁을 때:** 칩 줄은 가로로 스크롤한다(줄 바꿈 없음). 띠가 덮은 높이에 다 들어가지 않으면 줄 단위로 아래부터 뺀다. 모드 단추는 늘 남긴다.
- **말:** 띠는 `aria-label="Claude Code 상태"`인 `section`이다. 값이 바뀔 때마다 읽어 주지 않는다. 모드가 바뀌면 "모드: <이름>"을 polite로 한 번.
- 띠를 누르면 입력창에 초점이 간다(칩과 단추는 제 일을 한다).

### 3.4 전환

- **"터미널 입력칸 보기"**: 기기마다 localStorage, 기본은 꺼짐(감춤). PC는 머리글 단추(`aria-pressed`), 폰은 "더 보기" 메뉴의 체크 항목이다. 켜면 덮개와 띠가 사라지고 지금과 같다.
- "Claude Code 창 알아보기"를 끄면 감추기도 멈춘다.

## 4. 입력을 넘겨받기

### 4.1 친 글과 초점(고르는 창 설계 §9.6을 따른다)

덮개가 있을 때:

- PC에서 터미널을 열면 초점은 입력창에 간다.
- PC에서 터미널을 누르면 입력창에 초점이 간다. 끌어서 글을 고르는 것은 그대로 된다.
- 아무 데서나 친 글자(결정 188)는 입력창으로 가고 입력창이 초점을 받는다. Enter, Backspace, 화살표는 터미널로 보내지 않는다. 한글 첫 음절이 깨질 수 있는 것은 결정 188과 같다.
- 붙여 넣은 글과 파일, 터미널 칸에 끌어 놓은 파일의 경로는 입력창에 들어간다(결정 220과 같은 길).
- 폰에서 터미널을 누르면 아무 일도 하지 않는다. 초점도 주지 않는다. 입력창에 초점이 가면 자판이 올라와 터미널이 줄고 Claude Code가 다시 그리기 때문이다(내가 정함). 읽고 스크롤하는 것은 그대로 된다.
- **PC의 조작 키**(사용자가 고름): 입력창이 비었을 때 Esc와 Ctrl+글자(Ctrl+V는 빼고)는 터미널로 간다. Claude Code 입력칸에서 누른 것과 같다. 빗금 목록이 열려 있으면 Esc는 목록을 닫고, 거절하고 지시 중이면 그것을 거둔다(지금과 같다). 한글을 조합하는 중이면 보내지 않는다. 글이 있으면 입력창의 편집 키다. Shift+Tab은 초점 옮기기로 두고, 모드는 모드 단추로 바꾼다. 결정 188과 다르므로 결정 217에 적는다.
- **폰의 조작 키**(Esc, ⌃C, ⇧Tab, 화살표)는 빠른 키로 지금처럼 터미널에 간다.
- 고르는 창이 떠 있을 때의 키는 결정 221을 따른다.

### 4.2 입력칸이 비었는지

`❯ ` 뒤의 칸 가운데 글자가 있는 칸이 모두 **같은 회색**이면(안내나 제안) 빈 입력칸이다. 회색은 RGB의 세 값이 8 안쪽으로 같고 64~200인 색, 또는 팔레트의 8번과 240~250번이다. 그 밖의 경우, 곧 기본색이나 다른 색(`ultrathink` 무지개, 색이 있는 자리표시나 `@` 언급) 글자가 한 칸이라도 있거나 회색이 둘 이상 섞였으면 실제 글이다. 틀리면 실제 글 쪽으로 틀린다: 덮지 않고 "글이 있습니다"를 띄운다(§1.3의 첫째를 피함, 내가 정함). 입력칸이 여러 줄이면 모든 줄을 본다. 브라우저의 xterm 칸에서 색 값까지 읽는다(`getFgColorMode`, `getFgColor`). 화면 조각(`Shot`)이 글자 말고 색도 싣게 된다.

## 5. ↑로 지난 글 불러오기

### 5.1 서버

`GET /api/terminals/{t}/prompts?limit=200` → `{prompts: [{text, at}], source: "claude"}`.

- 그 호스트의 Claude Code 설정 폴더(`$CLAUDE_CONFIG_DIR`, 없으면 `~/.claude`)의 `history.jsonl`을 끝에서부터 4MB까지 읽는다.
- `project`가 그 터미널의 폴더(코어가 준 `cwd`)와 같은 줄만, 새것부터, 바로 앞과 같은 글은 하나로, `limit`(최대 500)개까지.
- `text`는 `display`다. `[Pasted text #N …]` 자리표시는 `pastedContents[N].content`가 있으면 그 내용으로 바꾸고, 해시뿐이면 그대로 둔다.
- 읽지 못한 줄은 건너뛴다. 파일이 없거나 읽지 못하면 `{prompts: [], source: "none"}`이다(오류가 아니다).
- Claude Code 터미널이 아니면 `{prompts: [], source: "none"}`.
- 시험은 진짜 `~/.claude`를 읽지 않는다(환경 변수로 임시 폴더).

### 5.2 입력창

- **↑**: 입력창이 비었거나 캐럿이 첫 줄에 있고, 고르는 창의 키(결정 221)도 빗금 목록도 받지 않을 때. 한 칸 오래된 글을 넣는다. 처음 누를 때 쓰던 글은 따로 둔다.
- **↓**: 지난 글을 보는 중이고 캐럿이 마지막 줄에 있을 때. 한 칸 새로운 글로, 끝에서는 쓰던 글로 돌아간다.
- 지난 글을 고치면 그 글이 쓰던 글이 된다(보던 자리는 잊는다). 보내면 목록 맨 앞에 더한다(다음에 서버가 다시 읽을 때 기록에 있다).
- 목록은 입력창이 처음 ↑를 받을 때 받고, 보낼 때마다 다시 받을 표시만 한다. 받는 동안 ↑는 한 번 기다린다.
- 서버가 `source: "none"`이거나 실패하면 이 기기에서 보낸 글(localStorage, 호스트와 터미널마다 100개)을 쓴다.
- 캐럿은 넣은 글의 끝에 둔다. 화면 읽기 프로그램은 넣은 글을 polite로 듣는다.

## 6. 흐린 안내와 제안

- 입력칸이 비었고(§4.2) 회색 글이 있으면 그 글이 **안내**다.
- 입력창이 비었으면 입력창의 안내 글(placeholder)이 "<안내> · Tab"이 된다. 없으면 지금 안내("여러 줄로 보내기 · ⌘Enter")다.
- 입력창이 비었을 때 Tab을 누르면 안내 글을 입력창에 넣는다(캐럿은 끝). 고치거나 보내는 것은 사람이 한다. 빗금 목록이 열려 있으면 Tab은 그 목록의 것이다.
- 안내가 바뀌거나 사라지면 따라 바뀐다. 덮개가 꺼져 있어도(터미널 입력칸 보기) 한다.
- 안내를 화면 읽기 프로그램에 따로 읽어 주지 않는다(placeholder는 이름표와 함께 읽힌다).

## 7. 시험과 견본

- 견본: 녹화에서 속성만 뽑은 손 견본(글은 바꿈)을 저장소에 넣는다. 원시 녹화는 넣지 않는다.
  - 빈 입력칸(기본색 `❯`), 일하는 중(회색 `❯`), 회색 안내가 있는 입력칸, 친 글이 있는 입력칸, 상태 줄 세 줄과 모드 줄.
- 판독: 입력칸과 덮을 줄, 비었는지, 안내 글, 상태 줄 조각, 막대 줄, 모드 이름.
- 화면: 덮개와 띠의 자리, 덮지 않을 때들, 전환, 친 글과 초점, ↑↓와 쓰던 글, Tab, 모드 단추.
- 서버: 기록 읽기(폴더, 순서, 중복, 자리표시, 깨진 줄, 파일 없음, 4MB 끝), Claude Code가 아닌 터미널.
- 손 확인: 격리 코어에서 가짜 claude가 위 화면을 그리게 하고, 390×844와 1440×900, 밝음과 어둠으로 본다.

## 8. 만드는 사람에게 맡기는 것

- 칩과 막대의 모양(astryx Badge·ProgressBar 안에서), 띠 안의 배치, 줄을 뺄 때의 순서.
- 상태 띠와 고르는 창 패널이 한 화면에서 바뀔 때의 순서(둘은 함께 뜨지 않는다).
- 기록 목록을 다시 받을 때.
- 견본의 글.

## 9. 만들며 확인할 것

만든 뒤, 그때 사용자의 승인을 받아 오늘처럼 보기 전용으로 녹화해 본다(실제 Mori를 건드리는 일이라 그때마다 묻는다). 그 전에는 가짜 claude와 견본으로 만든다.

1. 쉬는 동안 뜨는 다음 말 제안이 실제로 있는지, 있으면 색이 같은지(§2.1). 다르면 §4.2와 §6을 고친다.
2. 입력칸이 여러 줄일 때 둘째 줄부터의 모양.
3. 상태 줄이 없는 사용자(설정하지 않음)에서 입력칸 아래가 모드 줄 하나뿐인지.
4. 일하는 동안 입력칸 아래에 다른 줄(대기 글, 할 일 목록 같은 것)이 끼는지. 끼면 띠에 글 그대로 보인다.

## 10. 본 설계 §3에 더하는 결정

- **217을 바꿈:** "상태 줄과 모드 줄은 그대로 보인다"를 "입력칸부터 아래 줄을 모두 덮고, 그 자리에 Mori의 상태 띠를 그린다(223)"로. 빈 입력칸은 같은 회색 글만 있는 입력칸이다(흐림 속성이 아님, §2.1, §4.2). 덮개가 있을 때 PC의 빈 입력창에서 Esc와 Ctrl+글자(Ctrl+V 빼고)는 터미널로 가고, 폰에서 터미널을 누르면 아무 일도 하지 않는다(§4.1). 결정 188의 행 끝에 "(덮개가 있을 때 친 글은 결정 217)"을 덧붙인다.
- **223 상태 띠:** §3.3.
- **224 ↑ 지난 글:** §5.
- **225 안내와 제안:** §6.
- **226 기록 읽기 API:** §5.1.

## 11. 만들며 정한 것(2026-11-12)

- 견본의 상태 줄에는 그림 글자(✍️ ⚡)를 넣지 않았다. 손 견본의 칸 너비와 xterm의 너비가 다르기 때문이다. 그림 글자는 `readStatus` 시험의 글로 확인한다.
- 서버는 그 터미널에서 Claude Code가 도는지 묻지 않는다(`/commands`와 같다). 브라우저가 Claude Code 터미널에만 묻는다. 그 폴더의 글이 없어도 `source: "none"`이라, 브라우저가 이 기기에서 보낸 글로 물러난다.
- Claude Code가 아닌 터미널의 ↑는 이 기기에서 보낸 글만 쓴다. 쓰던 글이 비었으면 돌아올 때 읽어 주지 않는다. Tab으로 넣은 안내 글은 한 번 읽어 준다.
- "크기가 같다"는 두 크기를 다 알 때만 따진다. 이 기기의 크기를 아직 재지 못했으면 같다고 본다.
- 덮개는 보이는 화면이 끝에 있을 때만 덮는다(뒤로 스크롤하면 걷힌다).
- PC의 전환 단추는 모니터 그림이다(터미널 그림이 없다). 셸 수 같은 모드의 덧붙임은 두 배치 모두 띠의 칩이다. 입력창 위 알림은 경고 바탕(`.term-held`)이다. 알림이 뜨고 질 때 터미널 칸이 그 줄만큼 줄고 늘며, 터미널이 한 번 다시 그린다(멈춘 글·승인 대기 알림과 같다).
- 덮개가 뜰 때 입력창이 초점을 가져오는 것은 초점이 페이지나 터미널에 있을 때뿐이다. 덮개가 있을 때 페이지에서 친 글자 말고 다른 키는 아무 데도 가지 않는다. Ctrl+Shift+글자는 입력창의 것이다.
- 폰에서 터미널을 누르면 xterm이 스스로 입력 글상자에 초점을 준다. 덮개가 있는 동안은 그 글상자에 `inputmode="none"`을 줘서 화면 자판이 올라오지 않고 터미널 크기도 그대로다(손 확인에서 찾음).
- 입력칸은 안내 글에도 맞춰 커진다. 폰에서 긴 안내가 두 줄이 되어 입력칸이 단추보다 커졌으므로, 안내 글은 한 줄로 두고 자른다(손 확인에서 찾음). Chrome은 자르는 자리에 "…"를 그리지 않는다.
- 손 확인은 `.dev/manual/`의 가짜 claude(`fake3.py`: 전체 화면, 상태 줄 세 줄, 모드 줄, 빈 입력칸의 회색 안내)와 격리 코어 `.dev/test/pick`, 헤드리스 Chrome과 화면 밖 WebKit(가림 검사 끔)으로 했다. 390×844와 1440×900, 밝음과 어둠: 띠의 칩 5개와 막대 2개, 모드 단추와 Shift+Tab, Tab, Esc와 Ctrl+O(따로 누름), ↑ 두 번(시험 기록의 둘째, 첫째), 알림, 전환, 폰에서 터미널 누름(크기 그대로). 띠가 떠도 터미널 크기는 그대로였다(122×33, 47×33).

## 12. 최종 검토 뒤 고친 것(2026-11-12)

검토(새 검토자)에서 넷을 바로 고쳤다: 창이나 승인 요청이 떠 있으면 PC 모드 단추를 끈다(Shift+Tab이 그 창으로 가 편집을 모두 허락할 수 있었다). Windows·Linux에서 터미널에 고른 글이 있으면 빈 입력창의 Ctrl+C는 복사한다. 모드 줄의 "·" 앞 알림을 칩으로 남긴다. 기록에 1MB가 넘는 줄이 있어도 그 뒤를 읽는다.

미뤘던 작은 것 열둘도 사용자의 말("미룬 작은 것들 다 고쳐")로 고쳤다.

- 입력칸 아래에 모드 줄이 없으면 "모드: 기본"이다. 입력칸이 없을 때(고르는 창)만 마지막 모드가 남는다.
- 이름 없는 막대는 "상태 막대"로 읽힌다. 불러온 지난 글은 첫 줄의 60자까지만 읽어 준다.
- 보내기가 끝난 뒤 1초 동안 덮개를 그대로 둔다(코어가 터미널이 입력칸을 비우기 전에 답할 수 있다). 1초 뒤에도 글이 있으면 알린다.
- ↑로 기록을 받는 사이에 친 글이 있으면 불러온 글을 버린다.
- 자동으로 줄이 넘어간 문단에서는 ↑가 먼저 캐럿을 올리고, 첫 줄에서 브라우저가 캐럿을 맨 앞으로 옮기면 지난 글을 부른다. 지난 글을 보는 중이면 바로 더 오래된 글로 간다.
- 방금 보낸 글은 Claude Code 기록에 아직 없어도 맨 앞에 나온다(이 방문 동안 메모리에, 20개까지).
- 이 기기에 남기는 보낸 글은 Claude Code 터미널 것만, 호스트·주소·시작 시각마다(새 터미널이 같은 주소를 받아도 섞이지 않게), 30일까지다. 30일 넘은 터미널의 기록은 지운다. 셸 터미널에서 보낸 글은 이 방문 동안만 ↑로 다시 나오고 저장되지 않는다.
- 덮개가 있을 때 터미널 쪽(xterm이 초점을 가진 때)에 붙여 넣은 글은 입력창에 그대로 들어가고 입력창이 초점을 받는다.
- 폰에서는 안내 글에 "· Tab"을 붙이지 않는다. 덮개가 있고 입력창이 비었는데 안내가 있으면 빠른 키 Tab이 터미널 대신 입력창에 안내를 넣는다.
- 상태 띠가 넘치면 그릴 때마다 줄 높이를 재어, 들어가지 않는 아래 줄을 통째로 숨긴다(모드가 있는 첫 줄은 남긴다).
- 화면은 바뀔 때(쓰기, 스크롤, 초기화, 크기)마다 세대를 올리고, 같은 세대 안에서는 같은 조각을 돌려준다. 판독도 조각마다 한 번이다. 고르는 창과 상태 띠가 한 프레임에 화면을 한 번만 읽는다.
- `box.ts`의 쓰이지 않는 줄을 지웠다. 보내기가 끝난 순간의 덮개를 고정하는 시험을 더했다.
