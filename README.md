# Mori (몰이)

herdr-core(`hc`) 위에서 도는 원격 작업 웹앱입니다. 터미널 세션과 코딩 에이전트(Claude Code, Codex)를 폴더별로 띄우고, 승인·입력 대기 알림을 받고, Git 워크트리를 다룹니다. 휴대폰을 포함해 어느 기기의 브라우저에서든 씁니다. 밖에서는 Tailscale을 거쳐 접속합니다.

- **세션은 herdr-core에 삽니다.** 브라우저를 닫거나 Mori를 다시 띄워도 세션은 그대로입니다.
- **호스트마다 Mori 하나, 폰에는 앱 하나:** 세션을 돌릴 컴퓨터마다 Mori를 설치합니다. 폰은 그중 하나(허브)에만 페어링하고, 허브가 이은 다른 호스트의 세션과 알림을 함께 다룹니다. 한 호스트가 꺼져도 나머지는 계속 돕니다.
- **tailnet 안에서만:** Mori는 127.0.0.1에서만 듣습니다. 다른 기기에서는 `tailscale serve`가 주는 `https://<호스트>.<tailnet>.ts.net`으로 엽니다.

> 단계 11(여러 호스트를 한 앱에서)까지 만들었습니다. 허브의 화면에서 이은 호스트를 골라 열고, 허브의 설정에서 호스트를 잇고 관리합니다. 실제 기기에서 확인할 것(iPhone 홈 화면 앱의 입력과 알림, 허브를 거친 다른 호스트의 입력과 알림, Windows 호스트, 에이전트의 상태 보고)은 [설계](docs/superpowers/specs/2026-11-08-mori-design.md) §13과 §15에 남아 있습니다.

## 화면

폰과 PC가 같은 주소를 엽니다. 창의 폭이 768px보다 좁으면 폰 배치, 그 이상이면 PC 배치입니다.

- **폰:** 한 번에 한 화면입니다. 아래 탭으로 지금 볼 것, 폴더, 설정을 오가고, 지금 볼 것과 폴더의 오른쪽 위 + 버튼으로 새 세션을 엽니다. 세션을 누르면 터미널 화면이 열립니다. 제목 아래의 호스트 이름을 누르면 호스트 시트가 열립니다.
- **PC:** 왼쪽 사이드바(지금 볼 것, 폴더), 가운데 본문(터미널, 새 세션, 설정), 오른쪽 패널(Git, 커밋)입니다. 사이드바와 패널의 너비는 그 사이의 손잡이를 끌거나 방향키로 바꾸고, 손잡이를 두 번 누르면 기본 너비로 돌아갑니다. 너비는 기기마다 기억합니다. 헤더에는 호스트 선택, 새 세션, 화면 테마, 설정이 있습니다.
- **여러 호스트:** 허브에 다른 호스트를 이어 두면(아래 "여러 호스트를 한 앱에서") 한 번에 한 호스트의 화면을 봅니다. PC는 헤더의 호스트 선택, 폰은 호스트 시트에서 다른 호스트로 바꾸고, 거기에 호스트마다 세션 수(승인 대기 1 · 작업 중 2 같은)와 끊김·닿지 못함이 보입니다. 폴더나 설정에서 바꾸면 그 화면 그대로, 다른 화면에서 바꾸면 그 호스트의 지금 볼 것으로 갑니다. 다른 호스트에 승인 대기, 오류, 입력 대기인 세션이 있으면 호스트 이름 옆에 배지가 붙습니다. 배지의 숫자는 승인 대기, 오류, 입력 대기 순으로 가장 급한 것이 가장 많은 호스트 하나의 것이고, 누르면 그 호스트의 지금 볼 것이 열립니다. 페이지 제목과 앱 아이콘의 숫자는 모든 호스트를 더한 것입니다.
- **호스트 잇기와 관리:** 허브의 설정에 "연결한 호스트"와 "호스트 연결"이 있습니다. 호스트 선택과 호스트 시트 끝의 호스트 관리도 그리로 갑니다. "호스트 연결"에 그 호스트의 페어링 링크를 붙여 넣거나 주소와 코드를 넣어 잇고, "연결한 호스트"에서 호스트마다 연결과 알림, 버전을 보고 이름을 바꾸거나 연결을 해제합니다. 이은 호스트의 설정에서는 그 호스트의 하위 터미널 알림, 폴더, 프리셋을 바꾸고, 이 기기의 알림과 기기, 호스트 연결은 허브의 설정에서 바꿉니다.
- **끊김과 닿지 않음:** 이은 호스트가 허브의 연결을 해제했으면(끊김) 그 호스트의 화면 대신 "새 코드로 다시 연결"이 나옵니다. 누르면 허브의 설정에서 그 주소를 채운 "호스트 연결"이 열리고, 그 호스트에서 받은 새 코드만 넣으면 됩니다. 허브가 그 호스트에 닿지 못하면(그 컴퓨터가 꺼졌거나 잠들었을 때) "닿지 못했습니다" 배너가 뜨고, 지금 볼 것과 폴더는 마지막으로 본 목록을 흐리게 보이며 누를 수 없습니다. 목록이 없는 화면(폰의 터미널·Git·설정)에서는 배너가 "다시 연결하는 중입니다"라고 알립니다. 그동안에도 계속 다시 붙어 보고, "다시 시도"를 누르면 바로 다시 붙습니다.
- **다크 모드:** 시스템, 밝게, 어둡게 중에서 고르고 기기마다 기억합니다. PC 헤더의 버튼이나 설정의 "화면"에서 바꿉니다. 터미널은 두 모드 모두 어둡습니다.

| 화면 | 하는 일 |
|---|---|
| 지금 볼 것 | 살아 있는 세션을 승인 대기, 오류, 입력 대기, 작업 중으로 묶고, 묶음 안에서는 방금 바뀐 세션이 위에 옵니다. 숫자 배지는 승인 대기, 오류, 입력 대기를 더한 것입니다 |
| 폴더 | 등록한 폴더별 세션. 폴더마다 새 세션을 열고 Git 화면으로 갑니다 |
| 터미널 | 직접 입력합니다. 빠른 키(Esc, Tab, 화살표, Ctrl+C 등), 여러 줄 보내기, 파일 올리기(끌어다 놓기, 붙여넣기), 승인 대기의 응답 키, 보기 전용이 있습니다 |
| 새 세션 | 폴더와 프리셋(Claude Code, Codex, 셸)을 고르고, 있는 워크트리나 새 브랜치(새 워크트리를 만듭니다)에서 엽니다 |
| Git | 브랜치, 워크트리, 바뀐 파일과 diff. 워크트리를 고르거나 지웁니다 |
| 커밋 그래프 | 브랜치와 병합이 보이는 기록. 커밋을 누르면 상세와 diff를 봅니다. Git 화면에서 엽니다 |
| 설정 | 알림, 기기, 새 기기 페어링(QR, 코드, 링크), 화면 테마, 폴더, 연결한 호스트, 호스트 연결, 프리셋, 정보 |

## 요구 사항

| 무엇 | 버전 | 쓰는 곳 |
|---|---|---|
| herdr-core의 `hc` | 0.1.19 이상 | 세션 전부. 없으면 서버는 뜨지만 세션을 다룰 수 없습니다 |
| git | 2.36 이상 | 브랜치·워크트리·변경 보기 |
| Tailscale | MagicDNS와 HTTPS 인증서를 켠 tailnet | 다른 기기에서 접속 |
| OS | macOS, Windows 10 이상 | 서비스 설치. Linux는 빌드만 하므로 `mori serve`를 직접 띄웁니다 |

## 설치

1. **실행 파일 놓기.** 소스에서 빌드하려면 Go 1.26.5 이상과 Node.js 22.12 이상(npm 포함)이 필요합니다. go 명령이 go.mod의 툴체인(go1.26.10)을 받아 씁니다. `make release`와 `make build`는 웹 UI를 먼저 빌드해 실행 파일에 넣습니다. `npm ci`는 처음이나 `web/package-lock.json`이 바뀌었을 때만 돕니다.

   ```sh
   make release   # dist/mori-<os>-<arch>/
   ```

   - macOS: `mori`를 계속 둘 곳(예: `~/.local/bin`)에 놓습니다. 서비스는 설치할 때의 경로를 가리키므로 임시 디렉터리 안의 파일로는 설치하지 않습니다.
   - Windows: `mori.exe`와 `moriw.exe`를 같은 폴더에 둡니다. 로그인할 때는 콘솔 창이 없는 `moriw.exe`가 뜹니다.

2. **서비스 설치.** 로그인할 때마다 서버가 뜨도록 등록하고, 지금 바로 띄워서 응답을 기다립니다.

   ```sh
   mori service install            # --dry-run을 붙이면 할 일만 보여 줍니다
   ```

   - macOS: `~/Library/LaunchAgents/dev.mori.plist`(LaunchAgent)를 씁니다. 서버가 끝나면 launchd가 다시 띄웁니다.
   - Windows: `HKCU\…\CurrentVersion\Run`에 `Mori` 값을 씁니다. 관리자 권한이 필요 없습니다.
   - 옵션: `--home`(상태 디렉터리), `--listen`(기본 `127.0.0.1:7761`, 루프백만), `--public-url`(페어링 링크의 주소), `--hc`(hc 경로), `--hc-session`(herdr-core 세션, 기본은 이 셸의 `HC_SESSION`, 없으면 hc의 기본 세션)

3. **tailnet에 열기.** tailnet 관리 콘솔에서 MagicDNS와 HTTPS 인증서를 켠 뒤 실행합니다. Mori는 Tailscale 설정을 직접 바꾸지 않습니다.

   ```sh
   tailscale serve --bg http://127.0.0.1:7761
   ```

4. **점검.**

   ```sh
   mori doctor
   ```

   한 줄에 한 항목씩 `✓`(정상), `!`(주의: 일부 기능이 빠지거나 이 컴퓨터에서만 열림), `✗`(실패)로 보여 주고, 고칠 방법을 그 아래에 적습니다. `✗`가 있으면 종료 코드가 1입니다. 보는 항목은 Mori 버전, 상태 디렉터리 권한, 서버와 herdr-core 연결, hc·git 버전, Tailscale 이름과 `tailscale serve` 설정, 서비스 설치, 프리셋 프로그램(`claude`, `codex`)입니다. 읽기만 하고 아무것도 바꾸지 않습니다.

## 기기 페어링

```sh
mori pair --name "iPhone"   # 코드, 링크, QR을 보여 줍니다
mori devices                # 페어링된 기기
mori revoke <기기 ID>       # 페어링 철회. 그 기기의 열린 연결이 바로 끊깁니다
```

- 새 기기에서 QR을 찍거나 링크를 엽니다. 코드는 5분 동안 한 번만 쓸 수 있습니다.
- 페어링한 기기가 있으면 설정의 "새 기기 페어링"에서 "코드 만들기"를 눌러도 됩니다. 코드, 링크, QR이 나오고, 새 기기가 연결되면 알려 줍니다. 링크의 주소는 `mori pair`와 같습니다(`--public-url`, 없으면 이 컴퓨터의 Tailscale 이름). 설정의 "기기"에서 기기의 연결을 해제합니다.
- 페어링, 홈 화면 추가, 알림 켜기는 주소(origin)마다 따로 합니다. 호스트가 여럿이면 폰은 허브 하나에만 하고, 나머지 호스트는 허브에 잇습니다(아래 "여러 호스트를 한 앱에서").
- iPhone·iPad에서 알림을 받으려면 Safari의 "홈 화면에 추가"로 설치한 앱에서 열어야 합니다.

## 여러 호스트를 한 앱에서

폰에는 Mori 하나(허브)만 홈 화면에 추가하고 페어링합니다. 허브에 다른 호스트를 이어 두면 폰은 허브의 앱 하나로 그 호스트들의 세션을 열고 입력하며, 알림도 허브에서 받습니다. 어느 Mori든 다른 호스트를 이으면 허브가 됩니다.

1. 이을 호스트에서 페어링 코드를 만듭니다. 그 호스트에서 `mori pair`를 실행하거나, 그 호스트의 설정에서 "새 기기 페어링"의 "코드 만들기"를 누릅니다.
2. 허브의 설정에서 "호스트 연결"에 그 링크를 붙여 넣거나 주소와 코드를 넣습니다. 허브에서 명령으로 이어도 됩니다.

   ```sh
   mori hosts link 'https://desk.<tailnet>.ts.net/pair#code=ABCD-EFGH'
   mori hosts link https://desk.<tailnet>.ts.net ABCD-EFGH --name 책상
   mori hosts                # 이은 호스트: ID, 이름, 주소, 연결, 알림, 버전
   mori hosts unlink 책상     # ID나 이름으로 끊습니다
   ```

- 페어링 링크는 따옴표로 감쌉니다. zsh에서 `extended_glob`을 켰다면 `#`이 glob 문자가 됩니다.
- 이은 호스트의 기기 목록에는 허브가 "<허브 이름> 허브"로 보입니다. 거기서 철회하면 그 호스트와의 연결만 끊기고, 허브는 그 호스트를 "끊김"으로 둡니다. 새 코드로 다시 이으면 ID는 그대로이고, 이름도 `--name`을 주지 않으면 그대로입니다. 예전에 설정의 "다른 호스트"에 넣은 호스트도 "끊김"으로 남아 있다가 같은 방법으로 이어집니다.
- 허브에서 폰을 철회하면 그 폰은 허브를 거쳐 어느 호스트에도 닿지 못합니다.
- **알림:** 허브의 주소가 https(`tailscale serve`)면 허브가 이은 호스트의 알림을 구독해 폰으로 중계합니다. 폰은 허브의 알림만 켜면 되고, 알림을 누르면 그 호스트의 터미널이 열립니다. `mori hosts`의 알림 칸이 "끔"이면 `mori hosts link`가 이유를 보여 줍니다. 허브 설정의 "연결한 호스트"에도 그 이유와 "알림 다시 연결"이 보입니다. 허브의 주소가 바뀌면 중계가 꺼지므로 "알림 다시 연결"을 누르거나 새 코드로 다시 잇습니다.
- 허브와 이은 호스트의 버전이 달라도 됩니다. 허브의 화면이 그 호스트에 없는 기능을 부르면 그 화면만 오류를 보입니다. `mori hosts`의 버전은 이을 때 읽은 것입니다.
- 이은 호스트도 제 주소로 그대로 열립니다. 허브가 꺼져 있을 때 그 주소로 직접 열려면 폰을 그 호스트에도 페어링해 두어야 합니다.

## 업데이트와 제거

- **업데이트:** 서비스를 지우고, 파일을 바꾸고, 다시 설치합니다. Windows는 돌고 있는 `moriw.exe`를 덮어쓸 수 없으므로 이 순서를 지켜야 합니다. 세션은 herdr-core에 있으므로 그동안에도 살아 있습니다.

  ```sh
  mori service uninstall
  # mori(Windows는 mori.exe와 moriw.exe 둘 다)를 새 파일로 바꾼다
  mori service install
  ```

- **제거:** `mori service uninstall`은 서비스를 지우고 서버를 멈춥니다. 상태 디렉터리와 herdr-core, 그 세션은 남깁니다. 모두 지우려면 상태 디렉터리를 지웁니다. 그러면 모든 기기를 다시 페어링해야 합니다.

## 알아 둘 것

- **상태 디렉터리:** `--home`, 다음 `MORI_HOME`, 그다음 OS의 설정 디렉터리 아래 `Mori`입니다(macOS `~/Library/Application Support/Mori`, Windows `%AppData%\Mori`, Linux `~/.config/Mori`). 안에는 `state.json`(폴더, 프리셋, 기기, 알림 구독과 키, 이은 호스트), `mori.sock`(관리 소켓), `mori.log`(서비스의 로그)가 있습니다.
- **macOS의 PATH:** 서비스의 서버는 설치할 때 셸의 `PATH`로 hc, git, 프리셋 프로그램을 찾습니다. LaunchAgent의 기본 `PATH`에는 `/opt/homebrew/bin`이나 `~/.local/bin`이 없기 때문입니다. `PATH`를 바꿨다면 `mori service install`을 다시 실행합니다. 서비스가 설치되어 있으면 `mori doctor`도 그 `PATH`로 찾아 봅니다.
- **실행 파일을 옮겼다면** `mori service install`을 다시 실행합니다. 서비스는 설치할 때의 경로를 가리킵니다.
- **Windows의 Run 키:** 로그인 뒤 조금 늦게 뜰 수 있고, 안전 모드에서는 뜨지 않습니다. 명령은 260자까지만 보장되므로, 너무 길면 `mori service install`이 경고합니다. 서버가 비정상 종료하면 다음 로그인까지 다시 뜨지 않으니 `mori service install`로 다시 띄웁니다.
- **herdr-core:** 기본은 hc의 기본 세션, 즉 공식 Herdr 앱과 같은 코어입니다. herdr-core는 처음 자신을 띄운 프로그램의 환경을 모든 세션에 물려줍니다. 그래서 서비스는 정해진 환경으로 서버를 띄웁니다. macOS에서는 설치할 때의 `PATH`, 로캘, XDG 디렉터리 변수만 쓰고, Windows에서는 로그인 환경을 씁니다.
- **로그:** 서비스로 돌 때 `mori.log`에 덧붙이고, 패닉도 그 파일에 남깁니다. 로그를 돌려 쓰지 않으므로 너무 커지면 서버를 멈추고 지웁니다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `mori serve` | 서버를 실행합니다(`--home`, `--listen`, `--public-url`, `--log`, `--hc`, `--hc-session`) |
| `mori service install` / `uninstall` | 로그인할 때 서버를 띄우도록 설치하거나 제거합니다(`--dry-run`) |
| `mori pair` / `devices` / `revoke` | 기기를 페어링하고, 보고, 철회합니다 |
| `mori hosts` / `hosts link` / `hosts unlink` | 허브에 이은 호스트를 보고, 잇고, 끊습니다(`--home`, `hosts link`는 `--name`) |
| `mori doctor` | 설치와 연결 상태를 점검합니다(`--home`, `--hc`) |
| `mori version` | 버전, OS, Go 버전을 출력합니다 |

명령마다 `-h`로 옵션을 볼 수 있습니다.

## 보안

- **노출 범위:** Mori는 127.0.0.1에서만 듣고, 밖에서는 `tailscale serve`를 거쳐 tailnet 안에서만 닿습니다. HTTPS 인증서의 이름(`<호스트>.<tailnet>.ts.net`)은 공개 인증서 투명성(CT) 로그에 남습니다.
- **기기 인증:** 페어링한 기기만 들어옵니다. 기기 토큰은 JS가 읽을 수 없는 쿠키(SameSite=Strict)로만 오가고, 서버에는 해시만 저장합니다. 상태를 바꾸는 요청과 WebSocket은 `Origin`이 같은 호스트여야 합니다.
- **페어링 남용:** 코드는 한 번만 쓰고 5분 뒤 만료됩니다. 실패가 10분 안에 10번을 넘으면 그 창이 끝날 때까지 모든 페어링을 거절합니다.
- **코어 보호:** 브라우저는 herdr-core에 직접 명령을 보낼 수 없고, Mori가 정해진 동작만 중계합니다. git 경로는 등록한 폴더의 워크트리로 제한합니다.
- **허브:** 허브에 페어링한 기기는 허브가 이은 모든 호스트에 닿습니다. 허브는 정해진 API와 WebSocket만 넘기고(그 밖은 404), 폰의 쿠키 대신 그 호스트가 허브에 준 기기 토큰을 씁니다. 그 호스트의 쿠키와 보안 헤더는 폰에 넘기지 않습니다. 한 호스트만 떼려면 그 호스트에서 허브를 철회합니다.
- **알림 중계:** 이은 호스트가 보내는 알림(`/api/relay/<비밀>`)은 쿠키 없이 받습니다. 대신 경로의 256비트 비밀이 맞고 본문이 허브의 키로 풀려야 하며(RFC 8291), 그 경로는 로그에 남기지 않습니다.
- **로컬 파일:** 상태 디렉터리는 0700, `state.json`과 관리 소켓은 0600입니다(Windows는 사용자 프로필의 ACL을 따릅니다). `state.json`에는 알림 서명 키(VAPID 개인 키)와 토큰 해시가, 허브라면 이은 호스트마다 그 호스트의 기기 토큰(해시가 아닌 값)과 알림 중계 키가 들어 있습니다. 관리 소켓은 같은 사용자의 `mori` 명령만 씁니다.
- **서비스 환경:** macOS의 plist에는 `PATH`, 로캘, XDG 디렉터리 변수만 넣습니다. 셸의 토큰이나 키는 plist와 세션에 들어가지 않습니다.
- **응답 헤더:** 모든 응답에 CSP(`default-src 'self'`, 인라인 스크립트 금지), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`를 붙입니다.

## 개발

```sh
make build       # 웹 UI를 빌드한 뒤 bin/mori
make web         # 웹 UI만 internal/webui/dist에 빌드합니다
make test        # go test ./...
make test-web    # 웹 UI 테스트(Vitest, jsdom)
make vet         # go vet ./...
make release     # 웹 UI를 빌드한 뒤 darwin/arm64, darwin/amd64, windows/amd64, windows/arm64, linux/amd64
make vuln        # govulncheck: 코드가 닿는 알려진 취약점
make test-clean  # 통합 테스트가 남긴 격리 코어를 멈추고 지웁니다
```

- 통합 테스트는 실제 `hc`로 테스트마다 격리 코어를 띄웁니다. 세션은 `mori-test-<id>`이고, 소켓과 XDG 디렉터리는 저장소의 `.dev/test/<id>`에 둡니다. 사용자의 기본 코어는 건드리지 않습니다. hc가 없으면 그 테스트는 건너뜁니다. 다른 hc로 시험하려면 `MORI_TEST_HC`에 경로를 줍니다.
- 웹 UI는 `web/`의 Preact·TypeScript 앱입니다. Vite가 `internal/webui/dist`에 빌드하고, 실행 파일이 그 파일을 품습니다. 빌드 결과는 커밋하지 않습니다. `make web` 없이 `go build`만 하면 자리표시 페이지가 뜹니다. 그 페이지는 서버 정보를 보여 주고, `mori pair`의 링크로 연 기기만 페어링합니다.
- UI를 고칠 때는 `mori serve`(127.0.0.1:7761)를 띄워 두고 `cd web && npm run dev`를 실행한 뒤 Vite가 알려 주는 주소(`http://localhost:5173`)를 엽니다. `/api`, `/ws`, `/h/`(이은 호스트)는 서버로 넘어갑니다. 페어링은 `mori pair`의 코드를 페이지에 입력합니다.
