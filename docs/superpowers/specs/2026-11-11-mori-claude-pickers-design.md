# Claude Code 고르는 창을 Mori로 — 설계

- 날짜: 2026-11-11
- 상태: 사용자가 승인했다(2026-11-11). 결정 행 #212~#217은 본 설계 §3에 옮겼다. 단계마다 구현 계획을 따로 쓴다.
- 본 설계: `docs/superpowers/specs/2026-11-08-mori-design.md`. §11의 결정 행(#212~#217)은 2026-11-11에 그 §3에 옮겼다.
- 기준 판: Claude Code 2.1.322, hc 0.1.19, @xterm/xterm 6.0.0.
- 문서 출처: code.claude.com/docs/en/의 commands, interactive-mode, sessions, fullscreen, cli-reference, plugins/cli-reference(2026-11-11에 읽음).

## 요약

Claude Code 터미널에서 세 가지를 한다.

1. 화면 맨 아래에 뜬 번호 목록(승인 요청, 질문, /model 같은 고르는 창)과 그 아래의 안내 줄을 브라우저가 xterm 버퍼에서 알아보고, 입력창 위에 단추로 보인다. 터미널은 지금 승인 막대처럼 그만큼 줄어든다. 못 알아보면 지금처럼 터미널 그대로다.
2. /resume과 /plugin은 Mori 시트에서 고르고, 값이 정해진 인자(/effort high, /fast on …)는 빗금 목록에서 고른다.
3. 터미널의 빈 입력칸을 덮어 감추고, 모든 글은 Mori 입력창으로 보낸다. 기기마다 다시 보이게 할 수 있다.

순서는 1 → 2 → 3이고, 단계마다 따로 내보낸다.

### 쓰는 말

- **입력창:** Mori의 여러 줄 보내기(Composer).
- **입력칸:** 터미널 안에 Claude Code가 그린 입력 자리(`❯`).
- **창:** Claude Code가 터미널에 띄운 고르는 창, 답 창, 정보 창.
- **패널:** Mori가 입력창 위(승인 막대 자리)에 띄우는 것. 모달이 아니고, 승인 막대처럼 터미널을 그만큼 줄인다.
- **시트:** Mori의 `components/Sheet.tsx`. PC는 Dialog, 폰은 BottomSheet.
- **빗금 목록:** 입력창 맨 앞의 `/`가 여는 명령 목록(#197).

## 1. 의도

### 1.1 사용자의 말 (2026-11-11)

> /model, /plugin 과 같이 명령 입력 후 새로운 선택을 해야 하는 도구의 경우 여전히 터미널에서 선택해야 한다는 불편함이 있어. 이 참에 터미널 입력 부분을 아예 보여주지 않고 모든 입력은 이 입력창을 통해 하고, 선택항목 또한 ui로 보여질 수 있도록 개선되었으면 좋겠어.

> resume 명령이라던지, btw 많이 사용하고 그정도? 사람들이 많이 쓰는 명령어들에 대한 대비도 해야할 것 같아. 구현은 권고 순서대로 진행하면 될 것 같아.

사용자가 정한 것:

- 명령 뒤에 뜨는 고르는 창은 Mori UI로 고른다.
- 터미널의 입력 부분은 보이지 않게 하고, 입력은 모두 Mori 입력창으로 한다.
- /resume과 /btw를 많이 쓴다. 사람들이 자주 쓰는 명령도 챙긴다.
- 검토에서 권고한 순서(알아보기 → Mori 화면 → 입력칸 감추기)로 만든다.

질문 창에서 고른 답(2026-11-11):

- **화면 견본:** 사용자의 터미널을 읽어서 모은다(§10). 키는 보내지 않고 화면만 읽는다. 만드는 동안 사용자가 창들을 한 번씩 연다(10분쯤). 원시 화면은 임시 폴더에만 두고, 글을 바꾼 견본만 저장소에 넣는다.
- **패널 자리:** 패널이 뜨면 터미널을 패널만큼 줄인다(§6.4). 지금 승인 막대와 같다. 다른 기기의 터미널 크기도 따라 바뀌고, 항목이 터미널과 패널에 두 번 보인다는 것을 알고 고른 것이다. 내가 권한 "패널이 터미널 아래쪽을 덮는다"는 버렸다.

### 1.2 왜 (내가 읽은 것)

- 폰에서 터미널의 고르는 창을 쓰려면 작은 글자를 보며 빠른 키(↑↓, Enter)로 커서를 옮겨야 한다. 몇 번 누를지 세야 하고, 잘못 누르기 쉽다.
- 글을 넣는 곳이 둘(입력창과 입력칸)이면 어디에 쳐야 할지 헷갈린다. 입력칸에 남은 글은 입력창이 보낸 글 앞에 붙어 함께 보내진다.
- Mori는 폰에서도 에이전트를 다루려고 만든 것이다(본 설계 §1). 고르기와 글 넣기가 손가락에 맞아야 한다.

## 2. 목표, 목표 아님, 실패

### 2.1 목표

1. Claude Code가 번호 목록으로 묻는 것(승인 요청, AskUserQuestion, 계획 승인, /model 같은 고르는 창)을 Mori 단추로 고른다. 단추에는 화면의 항목 이름이 쓰인다.
2. /resume과 /plugin은 Mori 시트를 연다.
3. 값이 몇 개로 정해진 인자는 빗금 목록에서 고른다.
4. /btw 답 창과 정보 창은 Mori 단추로 닫고 넘긴다.
5. 터미널의 빈 입력칸은 감추고, 글은 모두 입력창으로 보낸다. 감춘 것은 언제든 다시 보인다.
6. 알아보지 못한 화면은 지금처럼 터미널과 빠른 키로 다룬다.

### 2.2 목표 아님

- 대화를 채팅 모양으로 다시 그리기. 터미널은 계속 원시 스트림 그대로다(#6).
- Claude Code가 아닌 에이전트.
- 헤드리스 모드(stream-json, SDK)로 Claude Code를 따로 띄우기.
- Claude Code 안에서 도는 mod나 플러그인. mod API에는 기본 고르는 창과 입력칸을 그릴 자리가 없다(2026-11-11 검토).
- 모든 창을 Mori로 옮기기. /config, /permissions, /hooks, /skills처럼 복잡한 창은 터미널에 둔다(§8).
- 알림의 답 단추(#196)를 화면의 항목 이름으로 바꾸기. 서버는 화면을 읽지 않는다.
- 나중 후보:
  - 새 세션 화면에서 지난 대화로 시작하기(`claude --resume <id>`).
  - 다른 작업 트리, 다른 폴더, 백그라운드 세션(`claude agents --json`)의 대화.
  - 입력창의 @ 파일 찾기와 보낸 글 기록.
  - AskUserQuestion의 Other에 글로 답하기(§6.4).

### 2.3 실패로 보는 것 (돌아가도 실패)

- 잘못 읽어 다른 항목을 누른다. 승인 요청에서는 더 나쁘다.
- 덮개나 패널이 질문, 오류, 승인 요청을 가린다.
- 터미널에 직접 손댈 길이 없어진다.
- Claude Code가 올라가 화면이 바뀌었을 때 조용히 깨진다. 틀린 단추가 뜨거나, 덮개가 엉뚱한 줄을 가린다.
- 창이 없는데 Esc나 화살표를 보낸다. 창이 없을 때 Esc는 Claude의 일을 멈추고(#188), ↑는 지난 글을 입력칸에 불러온다. 그 뒤에 Enter가 가면 지난 글이 다시 보내진다.
- 폰에서 지금보다 느려진다.

## 3. 제약

- **#6 터미널 그리기:** 원시 스트림을 xterm.js에 그대로 그린다. 이 설계는 그림을 바꾸지 않고, 브라우저가 이미 가진 버퍼를 읽기만 한다. 그래도 #6이 버린 "에이전트별 파서"를 Claude Code에 한해 쓰는 것이므로 §11에 행을 더한다.
- **#7·#125 터미널 크기:** 입력칸을 감추려고 pty 크기를 바꾸지 않는다(3단계). 패널은 사용자가 고른 대로 지금 승인 막대처럼 터미널을 줄인다(1단계). 그래서 패널이 뜨고 질 때마다 #125대로 `resize`가 가고, 같은 터미널을 보는 다른 기기의 크기도 바뀐다. 지금 승인 막대가 이미 그렇다.
- **#12 상태 출처:** 승인 대기(`blocked`)는 지금처럼 코어의 OSC 7501 보고로 정하고, 답할 질문의 ID(`ask`)도 결정 194 그대로다. 화면에서 읽은 것은 단추를 그리는 데만 쓰고, 상태를 정하지 않는다.
- **#124:** 승인 대기 중에는 입력창이 보내지 못한다(409 `blocked`). 바꾸지 않는다.
- **#194·#195:** 승인 요청에 답이 되는 키(번호, 창을 끝내는 Enter, Esc)는 `expect`를 실은 keys API로 보낸다. 커서만 옮기는 키(화살표, Space, Tab, ←→)는 `expect` 없이 keys API로 보낸다(§6.5). 2초 붙잡기는 `expect`를 실은 키에만 걸리므로 #194는 바꾸지 않는다. 거절하고 지시(#195)도 그대로다.
- **#197:** 빗금 목록은 "/name "을 넣고, 보내기는 사람이 한다. Mori 시트를 여는 명령만 바꾼다(§11 #215).
- **화면 지침(AGENTS.md, #201~#211):** 새 UI는 astryx를 따른다. 값은 토큰만 쓴다. 말은 `announce()`로 하고, 새 aria-live 영역은 만들지 않는다.
- **여러 호스트(#2):** 요청은 그 터미널의 호스트로 간다(`h.api`). 새 경로는 허브 중계 목록(`internal/server/api_proxy.go`)에 더한다.
- **Windows 호스트(#4):** 서버 쪽 새 코드는 macOS에만 있는 도구에 기대지 않는다.
- **시험:**
  - 격리 코어(`.dev/test/<id>`)에서만 한다.
  - 사용자의 계정이나 설정으로 진짜 `claude`를 돌리지 않는다.
  - 시험은 진짜 `~/.claude`를 읽지 않는다. CLAUDE_CONFIG_DIR를 넣는다.
- **대화 기록 형식:** 문서는 `<설정 폴더>/projects/<폴더>/<id>.jsonl`의 항목 형식이 내부의 것이고 판마다 바뀐다고 한다. 읽되, 못 읽으면 터미널로 돌아간다.

## 4. 지금 있는 것

- **입력창(`views/Terminal.tsx`의 Composer):** `POST /api/terminals/{t}/send`로 보낸다. 서버는 `hc send`(붙여 넣고 Enter)를 쓴다. 승인 대기면 409 `blocked`다(#124).
- **빗금 목록(#197, `views/Slash.tsx`):** 고르면 "/name "을 넣는다. `menu`인 명령(builtin.go의 `.opens()`)을 고르면 "보내면 터미널에 메뉴가 열립니다"를 띄운다.
- **승인 막대(AskBar):**
  - 단추는 1·2·3·Enter·Esc(폰은 Enter 없음)와 거절하고 지시다.
  - 번호 키는 이미 keys API로 보낸다. 승인 요청에서 번호 키가 먹는다는 것은 지금 막대가 이미 기대는 사실이다.
  - 막대의 글은 `status.msg`다.
- **빠른 키(폰):** Esc, Ctrl, Alt, Tab, ⇧Tab, ↑↓←→, Enter, ⌃C.
- **중단**(interrupt API), **파일 올리기**(붙여 넣기와 끌어 놓기도 된다).
- **`lib/xterm.ts`의 Screen:**
  - 버퍼를 읽는 메서드는 아직 없다.
  - `onView`가 스크롤, 초기화, 쓰기 뒤에 불린다.
  - `cell()`이 칸 하나의 CSS 픽셀이다.
- **서버의 `internal/commands`:** 내장 명령 표(builtin.go)와 설정 폴더 찾기가 있다. `ConfigDir`는 CLAUDE_CONFIG_DIR이고, 없으면 `~/.claude`다.

사용자의 Claude Code는 `"tui": "fullscreen"`이다. 대체 화면을 쓰고, 입력칸이 맨 아래에 고정된다. 2026-11-11 이 글을 쓰는 세션의 맨 아래:

───────────────────────────────────────────        가로줄

## 5. 큰 그림

| 단계 | 하는 것 | 기대는 것 | 끝났다는 기준 |
|---|---|---|---|
| 1 | 화면 맨 아래의 번호 목록과 안내 줄을 알아보고 단추로 만든다. 닫고 보내기 | 브라우저의 xterm 버퍼 | 견본 화면마다 맞게 읽는다. 못 알아본 화면은 지금 그대로다 |
| 2 | /resume·/plugin 시트, 인자 고르기 | 서버가 읽는 대화 기록, `claude plugin … --json`, 내장 명령 표 | 가짜 설정 폴더와 가짜 `claude`로 고르고 보낸다. 못 읽으면 "터미널에서 고르기"만 남는다 |
| 3 | 빈 입력칸 덮기, 전환, 모드 단추 | 1단계의 화면 읽기 | 빈 입력칸만 덮는다. 글이 있거나 창이 뜨면 덮지 않는다 |

- 단계마다 브랜치 하나로 끝내고, 따로 내보낸다.
- 서비스 교체는 그때마다 승인을 받는다.

## 6. 1단계 — 화면의 고르는 창 알아보기

### 6.1 어디서 읽나

- 브라우저의 xterm 버퍼(`term.buffer.active`)를 읽는다. 사람이 보는 화면 그대로이고, 칸마다 흐림(dim), 굵기, 반전, 색이 있다.
- 서버는 화면을 읽지 않는다. #6이 버린 "서버가 화면 텍스트를 폴링"은 그대로 버린다.
- `lib/xterm.ts`의 Screen에 버퍼 아래쪽을 주는 메서드를 더한다. 주는 것:
  - 줄마다 글자(`translateToString`)와 칸의 속성(`isDim`, `isBold`, `isInverse`, 색이 기본인지);
  - 버퍼 종류: `normal`이면 클래식 화면, `alternate`면 fullscreen;
  - `viewportY`, `baseY`, 행 수.
- 알아보는 일은 그 줄 묶음을 받는 순수 함수(예: `lib/pick.ts`의 `look`)가 한다. 그래야 견본(§10)으로 시험할 수 있다.
- Claude Code 터미널(`isClaude`)에서만 읽는다. `onView` 다음 프레임에 한 번 읽는다(한 프레임에 여러 번 불려도 한 번이다). 맨 아래 40줄까지만 본다.

알아본 결과의 꼴(만드는 사람이 다듬는다):

```ts
interface Look {
  seen: Seen | null   // 떠 있는 창
  box: Box | null     // 입력칸 (3단계)
  mode: string | null // 모드 줄의 글
}
interface Seen {
  title: string
  options: Option[]   // 번호 목록이 없는 창(안내 줄만)이면 []
  cursor: number      // 커서가 있는 항목 번호, 없으면 0
  hints: Hint[]       // 안내 줄에서 읽은 단추
  sig: string         // 창의 줄들로 만든 서명
}
interface Option { n: number; label: string; desc: string; mark: '' | 'on' | 'off' | 'current' }
interface Box { top: number; rows: number; empty: boolean } // top은 버퍼의 절대 줄
```

### 6.2 알아보는 것

**번호 목록**(Claude Code의 고르는 창). 예:

```
 Do you want to proceed?
 ❯ 1. Yes
   2. Yes, and don't ask again for git commands in /path
   3. No, and tell Claude what to do differently (esc)

 Esc to cancel · Tab to amend
```

- 항목 줄: `❯ N. 글`, 또는 같은 들여쓰기의 `  N. 글`.
- 설명 줄과 접힌 줄: 항목 사이에서 더 들여 쓴, 번호 없는 줄. 앞 항목에 붙인다.
- 제목: 첫 항목 위의, 빈 줄이 아닌 줄 1~3개. 테두리 글자(`│╭╮╰╯─`)는 걷어 낸다.
- 안내 줄: 마지막 항목 아래의 `<키> to <동작> · <키> to <동작>` 꼴.
- 표시: 글 앞의 체크 상자(여러 개 고르기)와 글 뒤의 `✔`(지금 쓰는 것). 정확한 글자는 견본으로 정한다.

**AskUserQuestion**(2026-11-11 이 설계를 쓰는 대화의 질문 창, fullscreen, 글은 바꿨다):

```
──────────────────────────────────────────────────────────────
 ☐ <머리>

│ <질문>

  1. <이름 앞부분>              ┌──────────────────────────┐
    <이름 뒷부분>               │ <미리보기>               │
❯ 2. <이름>                     │ │ ❯ 1. <미리보기 안의 글>│
                                ├─── ✂ ─── 6 lines hidden ─┤
                                └──────────────────────────┘

                                Notes: press n to add notes
──────────────────────────────────────────────────────────────
  Chat about this

Enter to select · ↑/↓ to navigate · n to add notes · Esc to cancel
```

- 창이 맨 아래를 모두 차지한다. 입력칸, 상태 줄, 모드 줄이 함께 사라진다(§13의 1).
- 항목에 미리보기가 있으면 항목 줄의 오른쪽에 상자가 그려진다. 상자가 있는 줄(`┌`부터 `└`까지)에서는 상자가 시작하는 칸부터 걷어 내고 왼쪽만 읽는다. 상자 안에는 번호 목록이나 `❯`처럼 보이는 글이 있을 수 있다. 이 견본의 상자 안에도 있었고, 상자 안에 상자가 또 있었다(34칸과 38칸).
- 칸은 글자 수가 아니라 화면 칸이다. 한글처럼 넓은 글자는 두 칸이다. 견본에서 항목 이름이 한글인 줄은 글자 수로 세면 상자가 25번째에서 시작해, 칸으로 센 34와 어긋났다.
- 이름이 길면 다음 줄로 접힌다. 미리보기가 있는 창에는 설명 줄이 보이지 않는다. 접힌 이름과 설명 줄은 들여쓰기로 가른다(견본으로 정한다).
- 맨 위의 `☐ <머리>`는 질문의 머리(탭)다. 여러 질문이면 여기에 탭이 늘어선다고 본다(§13의 4). 제목은 첫 항목 바로 위의 `│ <질문>`이다.
- 가로줄 아래의 `Chat about this`는 번호 없는 항목이다. 첫판에서는 단추로 만들지 않는다.

**입력칸:** 화면 폭을 거의 채운 가로줄, `❯`로 시작하는 줄 하나 이상, 가로줄. 3단계가 이것을 덮는다. 1단계에서는 "창이 떠 있지 않다"는 표시로 쓴다.

**모드 줄:** `⏵⏵ … on (shift+tab to cycle)` 같은 줄. 3단계의 모드 단추가 쓴다.

### 6.3 알아보는 규칙

아래가 모두 맞을 때만 목록으로 본다. 하나라도 어긋나면 목록이 없다고 본다(지금 화면 그대로).

1. 번호가 1부터 빠짐없이 이어지고, 항목이 둘 이상이다.
2. `❯`는 항목 줄 가운데 정확히 하나에 있고, 다른 항목 줄은 `❯` 자리만큼 들여 썼다. 줄 왼쪽 끝의 `❯`만 센다. 미리보기 상자 안의 것은 세지 않는다.
3. 마지막 항목이 화면 맨 아래에 가깝다. 그 아래에는 설명 줄, 빈 줄, 가로줄, 번호 없는 항목(`Chat about this`), 메모 안내(`Notes: …`), 안내 줄, 상태 줄과 모드 줄로 보이는 줄만 있고, 빈 줄이 아닌 줄은 정한 수(예: 10줄) 이하다. 미리보기 상자는 걷어 내고 센다. 2026-11-11 견본에서는 마지막 항목 아래가 16줄이었고, 상자를 걷어 내면 빈 줄이 아닌 줄은 넷이었다.
4. 목록 아래에 입력칸이 없다.
   - Claude Code는 창을 띄우면 입력칸 자리에 그린다고 본다(§13의 1). AskUserQuestion 견본(fullscreen)에서는 그랬다.
   - 이 규칙이 Claude의 답에 든 번호 목록을 걸러 낸다.
   - 견본에서 입력칸이 창과 함께 남는다고 나오면, 같은 뜻의 다른 경계(창을 두른 가로줄 같은 것)로 바꾼다. 뜻은 하나다: Claude의 답은 고르는 창으로 읽지 않는다.
5. 터미널이 Claude Code다.

번호가 없는 커서 목록(세션 고르는 창, /mcp 목록 같은 것)은 첫판에서 알아보지 않는다. `❯`는 입력칸 줄의 머리이기도 하기 때문이다.

알아본 창에는 서명(창의 줄 글자를 이은 것의 해시)을 붙인다. 누르기 바로 전에 다시 읽어, 서명이 같은지 본다.

### 6.4 패널

- **자리:** 입력창 위, 지금 승인 막대가 있는 자리다(폰은 `term-dock` 안). 모달이 아니다. 무엇을 묻는지와 차이 미리보기 같은 위쪽 화면이 계속 보여야 하기 때문이다.
- **터미널 크기(사용자가 고름):** 패널은 승인 막대처럼 터미널과 입력창 사이에 들어가고, 터미널은 패널 높이만큼 줄어든다. 패널이 뜨고 질 때 #125대로 `resize`가 가고 Claude Code가 다시 그린다. 같은 터미널을 보는 다른 기기의 크기도 따라 바뀐다. 항목은 터미널과 패널에 두 번 보인다.
- **크기가 흔들리지 않게(내가 정함):**
  - 같은 창(제목과 항목 이름이 같은 창)이 떠 있는 동안 패널 높이를 바꾸지 않는다. 커서가 옮겨 가거나 다시 그려져도 그대로다.
  - 패널 높이에 상한을 둔다. 줄어든 터미널에 창의 줄(제목부터 안내 줄까지)과 몇 줄이 더 남게 한다. 남지 않으면 패널 안에서 스크롤한다. 터미널이 창을 다 그리지 못하면 목록이 잘려 못 알아보고, 패널이 지고, 터미널이 다시 커지는 되풀이가 생기기 때문이다.
  - 패널 때문에 크기가 바뀐 뒤에는, 새 크기로 다시 그려질 때까지(1초까지) "창이 사라졌다"는 읽기를 믿지 않고 패널을 그대로 둔다. 그동안 단추는 잠근다.
- **승인 대기이고 목록을 알아봤으면:**
  - 번호와 Enter 단추 대신 화면의 항목 단추가 뜬다.
  - Esc와 거절하고 지시는 그대로다.
  - 머리의 "승인 대기 — 키로 응답"은 "승인 대기 — 골라서 응답"이 된다.
- **승인 대기가 아닌데 알아봤으면**(/model 등): 같은 모양의 고르는 목록 패널이 뜬다. 머리는 창의 제목이고, 제목이 없으면 "터미널이 고르기를 기다립니다"다.
- **항목:**
  - 한 상자에 이은 줄이다(`.qrows`, astryx의 List와 Item).
  - 줄마다 번호, 이름, 설명(보조 글자)이 있다.
  - 이름은 Claude Code가 쓴 그대로이고, 번역하지 않는다.
  - 커서가 있는 줄은 accent-muted 바탕이다.
  - `✔`와 체크 상자는 아이콘과 글로 보인다. 색만으로 알리지 않는다.
  - 폰에서 줄 높이는 44px 이상이다.
- **길이:** 패널이 길면 위의 상한에서 자르고, 안에서 스크롤한다. 상한은 화면 높이의 절반을 넘지 않는다.
- **여러 개 고르기와 여러 질문**(AskUserQuestion의 탭): 첫판은 항목을 보여 주기만 한다. 누르기는 커서 옮기기와 안내 단추(Space, Enter, ←→)로 한다. 견본을 보고 다음 판에 다듬는다.
- **Other에 글로 답하기:** 첫판에서는 하지 않는다.
  - 승인 대기 중에는 입력창이 보내지 못한다(#124).
  - 거절하고 지시(#195)나 터미널을 쓴다.
  - 다음 판의 후보는 `expect`를 실은 "글로 답하기"다. Other로 옮긴 뒤 글을 강제로 넣는다.
- **안내 단추**(§6.6)는 항목 아래 한 줄에 둔다.
- **말:** 패널이 새로 뜨면 `announce('고르는 목록: <제목>')`(polite)를 한다.
- **보기 전용**이면 패널을 보여 주되 단추는 끈다.

### 6.5 누르기

**승인 대기**(`blocked`, `ask` 있음). 키를 둘로 가른다(내가 정함):

- **답이 되는 키**(번호, 창을 끝내는 Enter, Esc): 지금처럼 keys API에 `expect`를 실어 보낸다(#194). 두 기기의 경쟁, 바뀐 질문, 2초 안에 다시 간 답은 서버가 막는다.
- **옮기는 키**(화살표, Space, Tab, ←→): 누르기 바로 전에 서명을 보고, keys API로 `expect` 없이 보낸다.
  - `expect`를 실으면 서버가 그것을 답으로 보고, 2초 동안 같은 질문의 다음 키를 막는다. 뒤따르는 Enter가 막히므로 싣지 않는다.
  - 답이 되는 키와 같은 길(keys API)로 차례대로 보내야 순서가 섞이지 않는다.
- 어느 키가 답이 되는지 견본으로 알 수 없으면 답이 되는 키로 본다(§13의 2). 막히더라도 다른 질문에 답이 가지는 않는다.
- 항목 1~9는 번호 키 하나다.
- 번호가 10 이상인 항목: 옮기는 키로 커서를 옮기고, 화면에서 커서가 그 줄에 온 것을 본 뒤(1.5초까지), Enter를 `expect`와 함께 보낸다.
- 안내 단추(§6.6)도 같다. Esc는 답이 되는 키이고, 화살표는 옮기는 키다.
- `ask`가 없으면 지금처럼 attach로 보낸다.
- 여러 질문의 AskUserQuestion이 승인 대기로 보고되면, 중간 질문의 번호도 `expect`를 싣는다. 2초 안에 다음 질문에 답하면 "이 질문에는 방금 답이 갔습니다"로 막힐 수 있다. 견본을 본 뒤(§13의 4) 다음 판에 다듬는다.

**그 밖의 목록:** 옮기고, 보고, 고른다.

1. 누르기 전에 서명이 그대로인지 본다.
2. 커서에서 고른 줄까지 ↑나 ↓를 그 수만큼 보낸다. attach(`link.send`)로 보내고, 그것이 없으면 keys API로 보낸다.
3. 화면에서 커서가 그 줄에 온 것을 본다(1.5초까지).
4. 그때 Enter를 보낸다.

- 커서가 다른 줄에 오거나, 목록이 바뀌거나 사라지거나, 시간이 지나면 Enter를 보내지 않는다. "목록이 바뀌어 고르지 않았습니다"를 알린다(`announce`, assertive).
- 번호 키는 쓰지 않는다. 어떤 창에서는 글자가 찾기를 시작한다(세션 고르는 창, 문서).
- 두 기기가 함께 눌러도 3에서 걸린다.

누르는 동안 패널의 단추는 잠근다(지금 막대의 `busy`와 같다).

### 6.6 안내 줄을 단추로

- 안내 줄을 ` · `로 나누고, 조각마다 `<키> to <동작>`을 읽는다.
- 아는 키만 단추로 만든다: Enter, Esc, Tab, Shift+Tab, Space, ↑/↓, ←/→, Shift+←/→, Ctrl+<글자>, 글자 하나. 바이트는 `lib/keys.ts`를 쓴다.
- 아는 동작은 우리말로 쓴다:

  | 동작 | 단추 |
  |---|---|
  | select, confirm | 고르기 |
  | cancel, exit, close, dismiss | 닫기 |
  | navigate | 위·아래 화살표 |
  | scroll | 위로, 아래로 |
  | copy | 복사 |
  | this session only | 이 세션만 |
  | adjust effort | 노력 낮추기, 노력 높이기 |

- 모르는 동작은 영어 그대로 키와 함께 쓴다(예: "f · fork").
- delete, remove, clear, discard 같은 낱말이 든 동작은 danger 모양으로 끝에 둔다.
- 글을 넣어야 하는 동작은 첫판에서 단추로 만들지 않는다: amend(Tab, 승인 요청에 말을 덧붙이기)와 add notes(`n`, AskUserQuestion에 메모 달기). 승인 대기 중에는 입력창이 보내지 못하므로(#124), 넣을 글을 보낼 길이 없다. 거절하고 지시(#195)가 비슷한 일을 한다.
- 승인 대기 중이면 단추의 키를 §6.5의 두 갈래(답이 되는 키, 옮기는 키)대로 보낸다.
- 번호 목록이 없는 창(/btw 답, 정보 창)에도 안내 줄만으로 패널이 뜬다. 조건은 안내 줄이 맨 아래에 가깝고, 그 아래에 입력칸이 없는 것이다.
- 단추를 누르기 전에도 서명을 다시 본다. 창이 없는데 Esc나 화살표가 가면 안 된다(§2.3).

### 6.7 /btw

- **보내기:** 그대로 된다. 입력창에서 "/btw 질문"을 보내면, Claude가 일하는 중에도 따로 답하고 하던 일은 멈추지 않는다(문서). 확인만 한다(§13).
- **답 창:** 문서에 따른 키:
  - Space, Enter, Esc: 닫기;
  - ↑↓: 스크롤;
  - Shift+←→: 이전 답, 다음 답(`[`·`]`와 Tab·Shift+Tab도 같다);
  - `c`: 복사;
  - `f`: 뒤에서 도는 하위 에이전트로 넘기기;
  - `x`: 지난 답 목록 지우기.

  창의 안내 줄을 §6.6으로 읽어 닫기, 위로·아래로, 이전 답·다음 답 단추를 띄운다. 안내 줄이 없거나 달라서 못 읽으면, 견본을 보고 /btw 답 창의 규칙을 따로 더한다.
- **복사:**
  - Claude Code의 `c`는 호스트의 클립보드나 OSC 52로 가므로, 폰에는 오지 않을 수 있다.
  - Mori의 복사는 화면에 보이는 답 글을 버퍼에서 읽어, 누른 그때 `navigator.clipboard.writeText`로 넣는다.
  - 스크롤에 가려진 부분은 들어가지 않는다고 알린다.
- **답 창이 떠 있을 때 보내기:** §6.8을 따른다.
- 빗금 목록의 자주 쓰는 명령(`lib/slash.ts`의 `COMMON`)에 `btw`를 더한다.

### 6.8 열린 창 위에서 보내기 ("닫고 보내기")

- **문제:** 창이 떠 있을 때 입력창이 붙여 넣은 글은 그 창으로 간다. 세션 고르는 창에서는 글자가 찾기를 시작하고, 뒤따르는 Enter가 맨 위 대화를 연다(문서).
- 승인 대기가 아닌 알아본 창이 떠 있으면, 보내기 단추가 "닫고 보내기"가 된다.
- 누르면:
  1. 서명을 다시 본다.
  2. Esc를 보낸다.
  3. 창이 사라지고 입력칸이 보이기를 2초까지 기다린다.
  4. 그때 보낸다.
- 그래도 창이 있으면 보내지 않고 글을 남긴다. 입력창 위에 "창이 닫히지 않아 보내지 않았습니다"를 띄우고, `announce`(assertive)를 한다.
- 승인 대기는 지금처럼 409 `blocked`와 거절하고 지시(#195)가 맡는다.
- 못 알아본 창은 지금과 같다. Mori가 알 수 없다.

### 6.9 못 알아볼 때와 끄기

- 못 알아보면 지금 화면 그대로다. 승인 막대는 1·2·3·Enter·Esc이고, 다른 창은 터미널과 빠른 키로 다룬다.
- 기기 설정에 "Claude Code 창 알아보기"(Switch, 기본 켬)를 둔다.
  - 끄면 1단계와 3단계가 모두 멈춘다.
  - 알아보기가 틀릴 때 사람이 바로 비켜 갈 길이다.

## 7. 2단계 — Mori의 고르는 화면

### 7.1 여는 길과 보내기

- 빗금 목록에서 /resume(/continue)이나 /plugin을 고르면, "/name "을 넣는 대신 그 시트를 연다.
- 입력창에서 인자 없는 "/resume", "/continue", "/plugin"을 보내면, 보내지 않고 시트를 연다.
- 인자가 있으면("/resume my-run", "/plugin install x") 그대로 보낸다.
- 시트마다 "터미널에서 고르기"가 있다. 인자 없는 명령을 그대로 보내 Claude Code의 창을 쓴다. 시트가 목록을 읽지 못해도 이것은 남는다.
- **시트에서 고른 것이 곧 보내기다.** #197의 "보내기는 사람이 한다"를 이 시트에 한해 바꾼다. 까닭:
  - 시트는 고르려고 연 창이다.
  - 줄마다 무엇을 하는지 쓰여 있다.
  - Claude Code의 창에서도 Enter가 바로 고른다.
- 시트는 `components/Sheet.tsx`다. PC는 Dialog, 폰은 BottomSheet이고, 제목은 heading-3이다.

### 7.2 /resume — "이전 대화 이어 하기"

**서버:**

- `GET /api/terminals/{t}/sessions`가 `{sessions: [{id, title, name?, first?, branch?, modified_ms, size}], partial}`를 준다.
- 폴더는 프로그램의 폴더다(`foreground.cwd`, 없으면 터미널의 `cwd`; #197과 같다). 설정 폴더는 `ConfigDir()`다.
- 기록 폴더 이름은 폴더 경로의 영숫자 아닌 글자를 `-`로 바꾼 것이다.
  - 200자가 넘으면 Claude Code가 자르고 해시를 붙인다(문서).
  - 그 폴더가 없으면, 앞 200자로 시작하는 폴더들에서 기록 안의 `cwd`가 맞는 것을 찾는다.
- `*.jsonl`을 고친 시각 순으로 최근 200개를 본다. 파일마다 앞 64 KB와 뒤 64 KB만 읽는다.
  - 찾는 것: 붙인 이름(/rename), 만든 제목(요약), 첫 사람 말, 가지(`gitBranch`).
  - 첫 사람 말은 명령, 도구 결과, 메타 항목을 건너뛰고 80자까지다.
  - 항목 이름은 견본으로 정한다(§13의 8).
  - (경로, 크기, 고친 시각)으로 기억해 두고, 다시 읽지 않는다.
- 빼는 것: 첫 말이 /loop인 대화와 `-p`나 SDK로 만든 대화(기록에서 알 수 있으면). Claude Code의 고르는 창도 이것을 뺀다(문서).
- 읽기는 3초까지 기다린다(#197과 같다). 넘으면 읽은 만큼을 `partial`로 준다.
- 지금 이 터미널의 대화를 알아낼 수 있으면 "이 대화"로 표시한다. 알아낼 수 없으면 표시하지 않는다(§12).

**화면:**

- 찾기 칸이 있다. 제목, 이름, 첫 말, 가지에서 찾고, 브라우저에서 거른다.
- 줄마다 제목이 있고(없으면 첫 말), 그 아래에 "3분 전 · main · 120 KB"가 있다. 최근 것이 위다.
- 누르면 `/resume <id>`를 보내고 시트를 닫는다.
  - id는 겹치지 않는다.
  - 이름은 겹치면 오류다.
  - 기본 표시 이름은 이어 하는 손잡이가 아니다(문서).
- 상태:
  - 비었으면 EmptyState("이 폴더에는 지난 대화가 없습니다")와 "터미널에서 고르기";
  - 읽기에 실패하면 오류 Banner와 "터미널에서 고르기";
  - 읽는 중에는 Spinner.
- 그 뒤 Claude Code가 "Resume this conversation?" 같은 창을 띄우면 1단계가 받는다.

### 7.3 /plugin — "플러그인"

**서버:** 그 호스트의 `claude` CLI를 셸 없이 argv로 부른다.

- `GET /api/terminals/{t}/plugins`: `claude plugin list --json`과 `claude plugin list --json --available`.
- `POST /api/terminals/{t}/plugins {action, plugin, scope}`. `action`은 install, uninstall, enable, disable이다.
- `GET|POST /api/terminals/{t}/plugins/marketplaces`: `claude plugin marketplace list|add`.
- 그 터미널의 폴더에서 부른다. 프로젝트 범위 때문이다.
- `claude`는 그 터미널이 돌리는 것과 같은 것을 찾는다. 못 찾으면 "claude를 찾지 못했습니다"와 "터미널에서 열기"만 보인다.
- 플러그인 이름(`^[\w.-]+(@[\w.-]+)?$`)과 마켓플레이스 출처(`owner/repo`나 https 주소)를 검사한다.
- 설치는 120초까지 기다린다.
- 시험에는 정해 둔 JSON을 내는 가짜 `claude`를 경로로 넣는다.

**화면:** 맨 위에 하나를 고르는 단추(`.seg`) "설치됨 · 찾기 · 마켓플레이스"가 있다.

- **설치됨:** 줄마다 이름, 설명, 범위가 있다. 켜기는 Switch이고 바로 적용된다. 제거는 확인 창(`btn-danger-fill`)을 거친다.
- **찾기:** 찾기 칸이 있고, 줄마다 이름, 설명, 마켓플레이스, 설치 단추가 있다. 범위는 사용자가 기본이고, 프로젝트도 고를 수 있다.
- **마켓플레이스:** 목록과 더하기 칸이 있다.
- 무엇을 바꿨으면 바닥의 주 단추 "이 세션에 적용"이 `/reload-plugins`를 보낸다. MCP 서버가 든 플러그인이 바뀌었으면 `--force`를 붙인다. 바꾼 것이 없으면 "닫기"만 있다.

### 7.4 인자 고르기 (빗금 목록의 둘째 칸)

- 입력창이 "/effort "처럼 명령과 빈칸이고 커서가 그 뒤에 있으면, 목록이 그 명령의 인자를 보인다.
- 고르면 "/effort high"를 넣는다. 보내기는 사람이 한다(#197 그대로).
- 둘째 칸에서 Esc를 누르면 닫힌다. 빈칸을 지우면 첫 칸으로 돌아간다.
- 인자는 `GET /api/terminals/{t}/commands`의 명령마다 `args?: [{value, desc?}]`로 온다.
- 내장 명령의 인자(builtin.go에 더한다, 문서 기준):

  | 명령 | 인자 |
  |---|---|
  | /effort | low, medium, high, xhigh, max, auto, status, ultracode on, ultracode off. 고를 수 있는 수준은 모델마다 다르다(문서) |
  | /fast | on, off |
  | /model | default, best, fable, sonnet, opus, haiku, sonnet[1m], opus[1m], opusplan. 설명에 "새 세션 기본값도 바뀝니다" |
  | /tui | default, fullscreen |
  | /context | all |
  | /mcp | reconnect all, enable, disable, 그리고 아래의 서버 이름 |

- 읽어서 채우는 인자:
  - /output-style: 기본 스타일과, 설정 폴더와 프로젝트의 `output-styles`;
  - /mcp: 설정에서 읽을 수 있는 서버 이름. 못 읽으면 하위 명령만 보인다.
- /model은 인자로도 고르고, 인자 없이 보내 1단계의 목록으로도 고른다. 목록에는 "이 세션만"(`s`)이 있어 인자와 다르다.

## 9. 3단계 — 터미널 입력칸 감추기

### 9.1 덮는 것

- §6.2의 입력칸, 곧 위 가로줄과 `❯` 줄과 아래 가로줄이다.
- `❯` 뒤가 비었거나(공백, nbsp) 흐린 글자(dim: 안내나 제안)뿐일 때 빈 입력칸이다.
- 상태 줄, 모드 줄, 일하는 중 표시는 덮지 않는다.

### 9.2 덮지 않을 때

- **입력칸에 글이 있을 때:** 다른 기기에서 터미널에 쳤거나, 지난 글을 불러왔거나, 대기 글을 되돌렸을 때다.
  - 덮지 않는다.
  - 입력창 위에 "터미널 입력칸에 글이 있습니다 — 보내면 그 뒤에 이어 붙습니다"를 띄운다. 지금도 일어나는 섞임을 알리는 것이다.
  - 처음 뜰 때 한 번 `announce`를 한다.
- **창(§6)이 떠 있을 때:** 입력칸이 없으니 덮을 것도 없다.
- **입력칸을 알아보지 못했을 때:** 덮지 않는다.

### 9.3 덮개

- 터미널 위에 겹친 상자 하나다.
  - 자리: (입력칸 첫 줄 − `viewportY`) × 칸 높이(`cell()`).
  - 높이: 줄 수 × 칸 높이.
  - 폭: 터미널 폭.
  - 바탕: 터미널 바탕색(`--term-*`).
- 오른쪽 끝에 작은 "입력칸 보기" 단추를 둔다(보조 글자). 폰에서는 44px이 들어갈 때만 둔다.
- `onView`마다 다시 잰다. 입력칸이 화면 밖으로 스크롤되면 숨긴다.
- pty 크기는 바꾸지 않는다(#7). 덮은 줄은 빈 띠로 남는다.
- 덮개는 `aria-hidden`이고, 단추만 초점을 받는다. z-index는 터미널 안쪽(2~3)에 든다.
- 클래식 화면(normal 버퍼)은 견본으로 입력칸 모양을 확인한 뒤 같은 규칙을 쓴다. 확인 전에는 fullscreen(alternate 버퍼)에서만 덮는다.

### 9.4 전환

- "터미널 입력칸 보기"는 기기마다 localStorage에 둔다. 기본은 꺼짐(감춤)이다.
- PC에서는 머리글의 단추(`aria-pressed`)이고, 폰에서는 "더 보기" 메뉴의 체크 항목이다.
- §6.9의 "Claude Code 창 알아보기"를 끄면 감추기도 멈춘다.

### 9.5 입력창이 넘겨받는 것

- **모드:** 모드 줄을 읽어 PC 입력창 줄에 "모드: <이름>" 단추를 둔다. 누르면 Shift+Tab을 보낸다.
  - 아는 이름은 우리말이다: accept edits → 편집 자동 허락, plan → 계획, bypass permissions → 묻지 않음, auto → 자동.
  - 이름은 `⏵⏵` 뒤에서 ` on` 앞까지다. ` on` 뒤의 글은 그때그때 다르다(`(shift+tab to cycle)`, `· 1 shell` 같은 것).
  - 모르는 이름은 그대로 쓴다. 창이 없는데 모드 줄이 없으면 "모드: 기본"이다.
  - 창이 떠 있는 동안에는 모드 줄이 사라지므로(§6.2), 마지막으로 읽은 모드를 그대로 둔다.
  - 폰에는 새 단추를 두지 않는다. 빠른 키의 ⇧Tab이 같은 일을 하고, 모드 줄은 화면에 보인다.
- **중단:** 지금 있는 중단(interrupt API)과 빠른 키의 Esc를 그대로 쓴다. 새로 만들지 않는다.
- **셸 모드:** 빈 입력칸에 `!`로 시작하는 글을 붙여 넣으면 셸 모드가 된다(문서). 입력창에서 "!ls"를 보내면 된다. 확인만 한다(§13).
- **이미지:** 파일 올리기가 맡는다.
- **나중 후보:** @ 찾기, Ctrl+R, 대기 글 되돌리기(↑). 그때까지는 "터미널 입력칸 보기"를 켜고 터미널에서 한다.

### 9.6 덮개가 있을 때 친 글

사용자의 말 "모든 입력은 이 입력창을 통해"를 따른다. 방법은 내가 정했다.

- **PC에서 터미널을 열면** 초점은 xterm이 아니라 입력창에 간다.
- **터미널을 누르면** 입력창에 초점이 간다. 끌어서 글을 고르는 것은 지금처럼 된다.
- **아무 데서나 친 키(#188):** 덮개가 있으면 친 글자는 입력창으로 가고, 입력창이 초점을 받는다. Enter, Backspace, 화살표는 터미널로 보내지 않는다. 결정 188과 다르므로 결정 217에 적고, 결정 188의 행 끝에 "(덮개가 있을 때 친 글은 결정 217)"을 덧붙인다.
- **붙여 넣기와 파일 올리기:** 붙여 넣은 글과 올린 파일의 경로(`quotePath`)는 터미널이 아니라 입력창에 들어간다.
- **폰에서 터미널을 누르면** xterm에 초점을 주지 않는다. 터미널의 자판이 올라오지 않는다.
- **조작 키**(Esc, ⌃C, ⇧Tab, 화살표)는 지금처럼 빠른 키와 단추로 터미널에 보낸다.
- **덮개가 없을 때**(창이 떠 있거나, 입력칸에 글이 있거나, "터미널 입력칸 보기"를 켰을 때)는 지금과 같다. 창이 떠 있을 때 친 키는 #188대로 창으로 간다.
- **그래도 터미널에 글이 들어가면**(다른 기기에서 쳤을 때 같은 것) 입력칸에 글이 보이므로 덮개가 걷히고 §9.2의 알림이 뜬다.
- 한글처럼 조합하는 입력의 첫 글자를 입력창으로 옮기는 방법은 만드는 사람이 정한다. #188처럼 첫 음절은 깨질 수 있다.

## 10. 시험과 화면 견본

**견본의 꼴:** 알아보는 함수는 줄 묶음(글자와 칸 속성)을 받는다. 견본은 그 묶음의 JSON이거나, 원시 바이트를 xterm에 써서 만든 묶음이다.

**필요한 견본:**

- §8 표에서 1단계와 안내로 다루는 화면 전부;
- 입력칸 넷: 비었을 때, 글이 있을 때, 흐린 제안만 있을 때, 여러 줄일 때;
- Claude의 답에 번호 목록이 있고 바로 아래에 입력칸이 있는 화면(걸러야 한다);
- 좁은 폭(40열쯤)에서 줄이 접힌 목록;
- 한글 항목(AskUserQuestion);
- fullscreen과 클래식;
- 미리보기 상자가 있는 AskUserQuestion(상자 안에 번호와 `❯`가 든 것).

**견본을 모으는 길(사용자가 고름):**

- 만드는 동안 사용자의 Claude Code 터미널을 `hc read --json`으로 1~2초마다 읽는다. 키는 보내지 않는다. 창이 떠 있는 화면만 남긴다.
- 사용자가 확인 목록의 창을 한 번씩 연다(10분쯤): /model, /resume, /btw 답, /plugin, /output-style, /theme, /export, /copy, /rewind, 묻지 않음 모드가 아닌 세션의 승인 요청, AskUserQuestion(여러 개 고르기, 여러 질문, Other).
- 이 설계를 쓰는 대화의 질문 창도 견본으로 쓴다(§6.2의 AskUserQuestion).
- 원시 화면은 임시 폴더에만 둔다. 사람의 일, 경로, 계정, 상태 줄의 값을 바꾼 견본만 저장소에 넣는다.
- `hc read`는 글자만 준다(칸 속성이 없다). 그래서 창을 알아보는 규칙은 글자만으로 서야 하고, 흐림과 색은 거들기만 한다. 칸 속성이 꼭 필요한 견본(3단계의 흐린 제안)은 §13의 11로 따로 모은다.
- `hc read`의 글에서는 넓은 글자도 한 글자다. 견본을 줄 묶음으로 바꿀 때는 xterm 버퍼처럼 화면 칸으로 펼친다(§6.2).

**시험:**

- `lib/pick.test.ts`: 견본마다 목록, 커서, 안내 단추, 서명, 덮을 줄.
- 화면 시험(vitest, xterm 대역):
  - 패널 단추가 맞는 키를 보내는가;
  - 서명이 바뀌면 보내지 않는가;
  - 커서가 오지 않으면 Enter를 보내지 않는가;
  - 패널 때문에 크기가 바뀐 뒤, 대역이 목록을 잘라 다시 그려도 패널이 지고 뜨기를 되풀이하지 않는가;
  - 승인 대기에서 옮기는 키는 `expect` 없이, 답이 되는 키는 `expect`와 함께 가는가;
  - 덮개가 있을 때 친 글자, 붙여 넣은 글, 올린 파일의 경로가 입력창으로 가는가;
  - 닫고 보내기, 전환, 설정 끄기.
- Go 시험: sessions(임시 CLAUDE_CONFIG_DIR의 가짜 기록), plugins(가짜 `claude`), commands의 `args`, 허브 중계.

**손으로 보기:**

- 격리 코어에 `claude`라는 이름의 대역 프로그램을 PATH로 띄운다. 대역은 견본 바이트를 그리고, 받은 키에 따라 다음 견본으로 넘어간다.
- 390×844와 1440×900에서, 밝게와 어둡게, 상태마다 본다(AGENTS.md).

## 13. 만들며 확인할 것 (견본으로)

1. 창이 뜨면 입력칸이 사라지는가(fullscreen과 클래식). §6.3의 4번이 여기에 기댄다. AskUserQuestion(fullscreen)은 확인했다: 입력칸, 상태 줄, 모드 줄이 모두 사라진다(2026-11-11). 다른 창과 클래식 화면은 남았다.
2. 창마다 안내 줄의 키와 동작 낱말은 무엇인가.
3. /model, /output-style, /theme, /export, /copy, /rewind, /memory, /login의 창이 번호 목록인가.
4. AskUserQuestion의 여러 개 고르기, Other, 여러 질문은 어떤 모양이고 어떤 키를 쓰는가.
5. /btw 답 창은 어떤 모양이고, 안내 줄이 있는가. 열려 있는 동안 입력칸이 남는가. 일하는 중에 답 창에서 누른 Esc가 일을 멈추지 않는가.
6. /model 창과 AskUserQuestion이 떠 있을 때 `status.state`는 무엇인가. /model은 `blocked`가 아니어야 §6.5의 두 길이 맞게 갈린다. AskUserQuestion이 `blocked`면 §6.5의 승인 대기 길을 탄다.
7. 일하는 중에 보낸 "/btw 질문"이 바로 도는가. 빈 입력칸에 붙여 넣은 "!ls"가 셸 모드가 되는가.
8. 대화 기록에서 이름, 제목, 첫 말, 가지가 든 항목은 어떤 형식인가.
9. `claude plugin list --json`과 `--available`은 어떤 모양인가.
10. Claude Code 프로세스의 폴더(`foreground.cwd`)가 대화 기록 폴더 이름의 기준과 같은가. 2026-11-11 이 대화의 세션에서 확인했다: `foreground.cwd`는 세션을 시작한 프로젝트 폴더였고, Bash 도구가 `cd`한 뒤에도 같았다. 작업 트리로 들어간 세션은 남았다. 다르면 §7.2의 폴더 찾기를 바꾼다.
11. 입력칸의 흐린 글(빈 입력칸의 안내, 다음 말 제안)은 어떤 속성(흐림, 회색 글자색)으로 그려지는가. `hc read`는 글자만 주므로 따로 확인한다. 방법(보기 전용 접속으로 원시 흐름 읽기 같은 것)은 그때 사용자에게 묻는다. 3단계는 이것을 확인한 뒤에 만든다.
12. 패널이 터미널을 줄였을 때 Claude Code는 창을 어떻게 다시 그리는가(목록을 자르는가, 안에서 스크롤하는가, 위쪽 글을 줄이는가). §6.4의 높이 상한이 여기에 기댄다.

## 14. 내가 정한 것

사용자가 정하지 않았고 내가 정한 것이다. 읽으며 확인해 주세요.

1. 화면은 서버가 아니라 브라우저가 xterm 버퍼에서 읽는다.
2. 항목 이름은 번역하지 않는다. Mori의 우리말은 머리와 아는 안내 동작에만 쓴다.
3. 패널은 모달이 아니고 승인 막대 자리에 뜬다(터미널을 줄이는 것은 사용자가 골랐다). 같은 창이 떠 있는 동안 패널 높이를 바꾸지 않고, 높이에 상한을 두고, 크기가 바뀐 뒤 1초까지는 패널을 그대로 둔다.
4. 번호 키는 승인 요청에만 쓴다. 그 밖에는 옮기고, 보고, 고른다. 승인 요청에서는 답이 되는 키(번호, Enter, Esc)만 `expect`를 싣고, 옮기는 키는 싣지 않는다. 모르는 키는 답이 되는 키로 본다. #194는 바꾸지 않는다.
5. 시트에서 고르면 바로 보낸다(#197을 /resume·/plugin에 한해 바꾼다). 인자 고르기는 넣기만 한다.
6. 인자 없는 /resume, /continue, /plugin을 보내면 시트를 연다.
7. /resume은 이 폴더의 대화만 최근 200개를 보이고, id로 보낸다. 다른 작업 트리, 백그라운드 세션, 새 세션 화면은 나중이다.
8. /mcp는 인자 고르기만 하고, 창은 터미널에 둔다.
9. /config, /permissions, /hooks, /skills 같은 창은 터미널에 둔다.
10. 창이 떠 있으면 "닫고 보내기"가 Esc로 닫은 뒤 보낸다.
11. "Claude Code 창 알아보기" 설정(기본 켬) 하나로 1단계와 3단계를 끈다.
12. 입력칸은 기본으로 감춘다. 덮개는 빈 띠와 "입력칸 보기" 단추다. fullscreen부터 한다.
13. 모드 단추는 PC에만 두고, 중단 단추는 새로 만들지 않는다.
14. /btw 답의 복사는 Mori가 화면 글로 한다. `COMMON`에 btw를 더한다.
15. 글을 넣어야 하는 것(AskUserQuestion의 Other와 add notes, 승인 요청의 amend)과 번호 없는 항목(`Chat about this`)은 첫판에서 단추로 만들지 않는다.
16. 이 글을 본 설계와 따로 두고, 결정 행은 승인된 뒤 본 설계 §3에 옮겼다(2026-11-11).
17. 덮개가 있을 때 친 글자, 붙여 넣은 글, 올린 파일의 경로는 입력창으로 가고, 터미널을 누르면 입력창에 초점이 간다(#188과 다르다). 사용자의 말 "모든 입력은 이 입력창을 통해"를 따른 것이고, 방법은 내가 정했다.
18. 화면 견본은 글자만으로 시험한다. 칸 속성이 필요한 3단계의 흐린 제안은 따로 확인한 뒤에 만든다.

아래는 1단계를 만들며 정한 것이다(2026-11-11, 계획 `docs/superpowers/plans/2026-11-11-claude-pickers-stage1.md`).

19. 창은 안내 줄이 있어야 알아본다. 번호 목록이 있어도 그 아래에 안내 줄이 없으면 창으로 보지 않는다.
20. 입력칸의 `❯` 줄은 커서로 읽지 않는다. 목록의 첫 항목이 입력칸 위나 안에 있으면 Claude의 답이거나 입력칸에 친 글이므로 읽지 않는다.
21. 설명은 항목 바로 아래에 빈 줄 없이 이어진, 더 들여 쓴 줄만이다. `Notes:`로 시작하는 줄(질문 창의 메모 안내)에서 끊는다. 항목 줄에서 두 칸 이상 띄운 뒤의 글도 설명이다.
22. `❯`는 항목 줄 가운데 꼭 하나에만 있어야 한다. 없거나 둘 이상이면 목록으로 읽지 않는다. 그 창이 안내 줄만 있는 창(24)으로 읽히면 안내 단추만 뜬다.
23. 누르기가 어긋나면 아무것도 보내지 않고 알린다. 창이 바뀌었거나, 커서가 1.5초 안에 그 항목에 오지 않으면 "목록이 바뀌어 고르지 않았습니다"다. 복사하지 못하면 "복사하지 못했습니다"다. 닫고 보내기에서 창이 닫히지 않으면 글을 남기고 입력창에 "창이 닫히지 않아 보내지 않았습니다"를 적는다.
24. 안내 줄만 있는 창(/btw 답, 정보 창)은 안내 줄이 빈 줄이 아닌 마지막 세 줄 안에 있고, 그 위에 가로줄이 있고, 입력칸이 없을 때만 알아본다. 이 창은 제목을 읽지 않으며, 패널 머리는 Mori의 글 "터미널에 창이 떠 있습니다"다. 패널에는 목록 없이 머리와 단추만 있다.
25. 보기 전용일 때도 패널은 뜨고, 그 단추는 잠긴다. 승인 막대 안의 목록은 잠그지 않는다. 보기 전용에서도 막대의 번호 키가 답하므로 목록도 같게 둔다.
26. 사라진 창을 붙잡는 것(입력칸이 보일 때까지 다시 띄우지 않음)은, 창이 보인 지 또는 패널이 터미널 크기를 바꾼 지 1초 안에 사라졌을 때만이다. 패널이 터미널을 줄인 탓일 수 있기 때문이다. 그 밖에는 1초 뒤 패널을 거두기만 한다.
27. 목록 높이의 상한은 창 id와 자리(패널인지 승인 막대인지)마다 한 번 정한다. 그 자리에 그린 뒤, 화면에 보이기 전에 잰다. 화면 높이의 반을 넘지 않고, 줄어든 터미널에 창의 줄과 입력칸 두 줄이 남도록 패널의 머리와 단추 몫까지 뺀다. 그래도 120px보다 작게 하지 않는다. 같은 창이 같은 자리에 있는 동안은 바꾸지 않는다(3).
28. 닫기 단추는, 안내 줄의 그 조각에 Esc가 있으면(`Space, Enter or Esc to close`) Esc를, 없으면 그 조각의 첫 키를 보낸다.
29. /btw 답 창의 `shift+←/→ to switch answers`를 "이전 답"과 "다음 답"으로 쓴 것은 짐작이다. 진짜 /btw 창의 안내 줄은 아직 보지 못했다(§13의 5).
30. `/`는 키로 읽지 않는다. `↑/↓`처럼 두 키를 잇는 글자이기 때문이다. 그래서 `/ to search`가 든 줄은 안내 줄이 아니다. `?`는 읽되 단추로 만들지 않는다(코어가 받지 않는 키다).
31. 닫고 보내기를 누른 때 창이 이미 없으면 Esc를 보내지 않고, 입력칸이 보이기만 기다린다. 창이 없을 때의 Esc는 일을 멈추기 때문이다(결정 214).
32. 화면 읽기(`Shot`)는 칸의 글자만 준다. 흐림, 굵기, 색은 3단계에서 더한다(§13의 11). 읽는 곳은 마지막으로 글자를 쓴 줄에서 위로 40줄이다. Claude Code는 높은 화면의 위쪽부터 그리므로(새로 열거나 /clear 한 뒤), 화면 맨 아래 40줄은 빈 줄뿐일 수 있다.
33. 제목은 첫 항목 위의 1~3줄을 이은 한 줄이다. 패널 머리는 한 줄이고, 넘치면 말줄임(…)으로 끝난다. 읽어 주기는 줄이지 않은 제목을 읽는다.
34. §6.1의 `Look.mode`(모드 줄)와 `Box.empty`(입력칸이 비었는지)는 1단계에 넣지 않았다. 쓰는 곳(모드 단추, 입력칸 덮개)이 3단계에 있다.
35. 폰의 승인 막대가 목록을 담으면 번호와 Enter 키가 목록으로 바뀌어 Esc만 남는다. 그 Esc는 "거절하고 지시"와 한 줄을 나눠 쓴다(1/4과 3/4, 둘 다 44px). 터미널이 60px쯤 커진다.
36. 문턱 값: 맨 아래 40줄을 보고, 목록 아래의 빈 줄 아닌 줄은 10줄까지, 제목은 3줄까지, 접힌 안내 줄은 3줄까지 이어 읽는다. 사라진 창은 1초 두고, 커서가 항목에 오기를 1.5초, 창이 닫히기를 2초 기다린다.

1단계를 손으로 확인했다(2026-11-11). 격리 코어(`.dev/test/<id>`)에서, Mori가 Claude Code 터미널을 여는 길 그대로 가짜 `claude`를 띄웠다. 1440×900과 390×844, 밝게와 어둡게 찍었다. 쉼, hover, 누름, focus-visible, 잠김(stale, 보기 전용)은 헤드리스 Chrome으로 보고, 쉼은 화면 밖 WebKit(WKWebView)으로도 보았다.

- WebKit도 Chrome과 같게 그렸다.
- 패널은 화면이 보일 때의 프레임에서 읽는다. 숨은 화면(다른 탭, 가려진 창, 내려 둔 앱)에서는 읽지 않고, 다시 보이면 읽는다.
- 이때 고친 것:
  - 27의 머리와 단추 몫. 12항목의 /theme가 1440×900에서 뜨지 않았다.
  - 32의 마지막으로 쓴 줄. 새 화면의 창이 맨 아래 40줄 밖에 있었다.
  - 35와 폰 승인 막대의 넘침. 막대가 목록 줄 제목의 폭을 따라 9px 넘쳤다.
  - 읽어 주기용 숨은 칸의 1px. 문서가 화면보다 1px 길어 화면 전체가 1px 스크롤되었고, WebKit은 그 옆에 스크롤 막대를 그렸다. 1단계 전부터 있던 잘못이다.
- 가짜로는 줄어든 터미널에 Claude Code가 창을 어떻게 다시 그리는지(§13의 12)를 알 수 없다. 진짜 Claude Code로 볼 일이다.
